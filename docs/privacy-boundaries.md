# 按需脱敏与内部数据完整性

2026-10-10：落实“受控内部保存完整原始数据，跨越信任边界时按需处理副本”。不以脱敏代替授权，也不以授权失败推断用户没有下达命令。

## 边界

| 用途 | 策略 |
|---|---|
| 请求、搜索状态、DST、检查点、工具参数、动作绑定、内部事件 | 原值序列化；内部读取不脱敏，不再维护字段豁免白名单 |
| SQLite 中上述内容 | 配置 `AUTOHUNT_DATA_KEY` 时新写入的 JSON/错误内容使用 Fernet 加密；读取后恢复同一原值 |
| HTTP 调试步骤、SSE、运行记录公开视图、审计日志 | 输出脱敏副本；不修改数据库内容或步骤 claim |
| 外部模型 | 投影请求、上下文、消息及原生 tool-call 参数 JSON；协议 ID 保留，原检查点不变 |
| MCP 返回值 | 注册边界统一投影结果，保留工具签名；不修改本地工具执行参数或存储 |
| 用户本人授权访问的简历原件 | 原有加密保存和访问控制保留，不为了日志/模型脱敏而改写原文件 |
| 已授权发送简历到模拟站 | 执行原有绑定原件的提交；必要联系方式属于本次授权数据，不将脱敏副本当简历发送 |

本次没有关闭真实站禁投、预览、一次性授权、简历绑定、验证接管或不确定结果禁止重放。

## 缩小脱敏范围

- 明确的联系方式/凭据字段，以及文本中可辨认的邮箱、电话号码、带标签姓名/家庭住址和密钥才做处理。
- 不把任意长数字视为电话号码。薪资、数量、分数、日期、公司名、城市、技术栈和长哈希保留。
- 结构化协议引用按 ID/hash/digest 类型保留标量，不靠为每个新业务字段增加白名单；嵌套对象不能借 ID 字段绕过敏感字段投影。
- 无标记的人名、地址和所有国家的电话格式不能靠本规则全面识别；这是范围明确的最小化，不宣称通用 PII/DLP。向模型构造上下文时仍应避免加入无关的私密原件、凭据与完整个人档案。
- 外部副本不用于判定原参数、授权摘要或检查点相等。

`runtime.store.safe_json` 现在只保证合法、无损 JSON；内部 `events()` 与边界 `public_events()` 分开。`redact`/`redact_text` 只用于需要脱敏的投影，不能用于 canonical state 写入。

## 兼容与限制

旧明文 JSON 可读取，与新加密记录共存，不主动批量改写历史。未配置数据密钥时本地运行库仍是明文，应限制本机目录/API 访问，不能导出或公开；会话标题/路由元数据不是本次加密载荷。错误/缺失密钥显式报错，不当作空状态继续执行。请保存原数据密钥；本次没有新增密钥或更改用户配置。

已经被旧脱敏改坏的授权摘要不能安全还原。不会猜原值、自动重签授权或重新投递。新计划不再发生同一序列化损坏；旧失败任务需要用户明确重新发起。此次只解决隐私边界和存储完整性，不声称岗位条件分支、重复总结或浏览器投递的其他问题全部已修复。
