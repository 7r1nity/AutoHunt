# 简历结构质量 MVP

## 已实现范围

AI 整理按钮在用户确认具体提供方、模型和当前简历后调用；上传不自动触发新整理功能。电话、邮箱及密钥模式在模型可见文本中脱敏，完整正文只留在本地加密文档。剩余正文仍可能敏感，确认框明确说明。

模型只输出原文 block ID、结构角色和原文短标题引用，不生成正文。覆盖行业中立的文档标题、章节、经历、字段、段落和待核对内容。预览/编辑从引用回填原文；技术、销售、设计、教学等均使用同一协议。

每次检查 JSON schema、来源存在、无重复、完整覆盖、顺序和标题前缀。非法输出最多纠错一次；超时直接保留原文。超过输入预算直接回退，不截断证据。无法分类的内容用 unassigned 显示，不遗漏。

模型、prompt/schema 版本、尝试次数与检查结果随文档加密保存。不记录明文提示词和供应商异常。编辑后结构失效；乐观版本锁避免晚到的整理覆盖新编辑。旧版本仍保留在现有加密历史中。

## 测试

在 agent 目录运行 `.venv/Scripts/python.exe -m pytest tests/test_resume_layout.py -q`。测试完全使用虚构数据和模型桩，不访问外部模型。覆盖多个行业、不同换行、数字/版本号、遗漏、重复、乱序、伪造来源、正文注入、超时、脱敏、版本冲突和加密存储。

## 明确边界与下一阶段

1. 引用完整不等于语义归类正确，也不证明用户履历真实。UI 明确提示仍需核对归属。
2. block 目前基于提取文本行；start/end 是 Unicode 文本偏移，不冒充 PDF 页码或版面坐标。OCR 错误和 PDF 阅读顺序需要后续布局解析。
3. 当前按原文顺序引用，不做跨行内部字符切片和自由重排序；混在同一行的多个字段可以保留待核对。
4. 材料补充仍走现有人工确认提案，尚未接入逐条事实来源校验；不能宣称所有功能已跨行业验证。
5. 下一步建立授权/脱敏的人工标注多行业留出集，评估经历边界、字段归属、贡献归属、数字单位关系；对照模型与 prompt 版本，设置发布门槛。当前模型桩只证明协议与防护有效，不代表模型准确率。
6. 不回接旧的“中文技术简历生成”prompt 作为导入路径。JSON 合规、第二模型审核和模型置信度都不能单独作为正确性证明。
