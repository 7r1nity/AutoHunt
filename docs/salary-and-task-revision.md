# 薪资条件与暂停修订（2026-10-11）

本版解决两条独立链路：暂停并修改后续条件时更新原任务；搜索薪资条件使用统一条件树，不被旧最低月薪字段二次否决。

## 暂停、修改、继续

规划模型获得同会话持久计划的紧凑快照（计划 ID、修订版本、步骤参数、状态和依赖）。修改用 `operation=revise` 与 `RevisionDraft` 参数增量，执行用 `operation=execute`；不从截短聊天重建已执行任务。

例如搜索进行中说「先暂停，85分以下但月薪25k以上的分析不足」：更新原计划未执行的成长步骤，保留 `max_score=84`、增加 `salary_min=25000`，仍依赖原搜索/总结完成。不会另起「暂停→立即生成计划」的 DAG。

- 修改先核对计划版本、会话及简历；只更新尚未执行的步骤，保留结果、任务 ID、依赖和其余参数。明确传 null 可清除可选参数。
- 参数变化后重新生成该步骤的动作绑定，不重复解析用户固定口令；保留原动作请求标志、撤回记录与审批保护。
- 暂停标志落入持久计划。后台观察器与执行器都不推进新动作，旧版本回写不能覆盖修订。
- 明确继续恢复同一任务，重新核对范围与简历，保留新增条件；不重复已完成步骤。服务重启后记录仍在，具体浏览器连接需原接续入口重建并核验登录。

限制：不能原地修改已开始或已完成搜索的查询参数、撤回的动作或结果不确定的写入。这样的条件调整需要明确新一轮搜索/重新核验，不会悄悄重放。暂停阻止后续动作，不等于撤销已发出的消息，也不保证立即抢占正执行中的不可撤销写入。

## 薪资模型

自然语言仍由模型解释，正则仅读取网站披露的薪资事实，不提取用户意图。模型输出 `filters` 的 `salary` 叶节点，使用元为单位：

| 请求 | 结构与判断 |
|---|---|
| 月薪15k以上，也可以面议 | `any(monthly minimum=15000, negotiable)`，面议是明确的 OR 例外 |
| 月薪15k–40k | 默认完整区间落入 `[15000,40000]`；明确允许交集时用 overlap |
| 工资15k | 若上下文无法判断最低门槛或期望薪资，针对性询问，不擅自猜测 |
| 实习日薪低于300不要 | daily minimum=300，限定实习；非实习及按月计薪岗位不受这个日薪条件排除 |

数值/面议叶节点由程序判断，同一 all/any/not 树可与 JD、福利、用工关系等模型证据判断组合。列表提前过滤与详情最终判断都使用该树；旧 `salary_min` 只是兼容叶节点，有完整月薪/面议树时不再形成独立门禁。兼容叶节点可替换或清除，不叠加旧门槛。

薪资未注明与面议不同，不能把日薪折算月薪，外币、年薪和时薪不冒充月薪。未知硬条件进入待核实，不计入符合数量，也不自动投递。仅实习条件而招聘类型不明时保留未知；已披露月薪不受「实习日薪」条件影响。搜索条件不会被移到投递或成长分支；当前成长工具的薪资范围仍只支持最低月薪，不声称已支持任意薪资树。启动提示、需求回顾与结果总结显示实际条件，不再同时宣称面议被排除。
