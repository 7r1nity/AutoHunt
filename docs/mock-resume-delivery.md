# 模拟站主简历绑定与受控投递

自动投递仅支持本地模拟站，真实招聘网站提交仍关闭。搜索、入队、沟通、收到回复与投递成功是不同状态。

## 投递链路

1. 用户预览并授权具体职位；一次性授权绑定主简历 ID、版本和内容摘要。
2. 执行器核对当前主简历仍启用且与授权一致，并绑定模拟站求职者账号。登录或验证仍由用户接管。
3. 招聘方回复后，向该账号同步授权的主简历文档；已有内容完全一致的副本会复用，不覆盖用户的其他简历。
4. 在发送前再次核对文档、账号、职位、模拟站简历内容和页面选择的简历 ID。任一不一致都停止，不能回退到第一份简历或演示简历。
5. 投递按钮只点击一次。即使点击抛异常，也只读取投递记录核对账号、职位和简历 ID；不能确认时标记结果不确定，禁止自动重试。

同步的是 AutoHunt 当前预览的主简历文档正文、技能与经历，不是模拟生成的候选人资料，也不是原始 PDF/DOCX 附件。模拟站结构化字段无法核实的学历留空；工龄使用站点数值字段的兼容值，同时保留 `unverified_fields` 元数据，页面显示“未核实”，不宣称候选人实际为零年经验。

## 模拟站依赖与生效

模拟站位于独立的 `C:\job_agent` 目录，不属于 AutoHunt 的 Git 仓库。配套页面需要提供 `selectedResumeId`、保留刷新前的简历选择，并禁止自动生成演示简历；旧页面不具备绑定能力时，执行器要求刷新而不是继续提交。

后端重新加载代码后生效；模拟站页面需刷新加载配套 JavaScript。已有失败或结果不确定的投递不会因升级而重试，需人工核对后重新预览授权。更新不会清除历史、主简历或申请看板。

## 搜索总结与规划

“搜索完成之后的总结呢”读取本会话绑定的实际搜索报告，包括整体薪资、招聘类型、福利、JD 概览与全部已记录职位简表；不是需求回顾，不创建新搜索，也不补答旧规划追问。未完成的搜索会明确说明当前进度。

城市规则只有完整消费的正向城市列表才具备覆盖权。不熟悉的城市、排除条件及其他未解析文本交给模型理解，不能用部分城市匹配覆盖模型结果。规划器恢复参数片段的授权时必须保存真实完整命令，执行层使用相同的授权语义。不同主题的学习目标不能因工具名称相同而合并；精确重复步骤合并后同步更新目标引用。

核验采用内存诊断、替身页面、JavaScript 沙箱和独立临时数据库，不执行真实搜索、沟通或投递。按仓库约定未恢复常驻自动化测试套件，当前没有持续自动回归覆盖。
