# 简历内容与排版约定

- 导入简历保留正文内容，不要求还原 PDF 的字体、分栏或坐标。
- 上传后、重新打开页面、设为主简历、接受导入提案后，默认展示排版简历。
- 原件仅作为备份入口；不将原件预览当作可编辑简历。
- 当前排版使用保守的章节标题识别和统一模板，不调用 LLM 改写正文；未知段落也保留。
- 导入和生成简历复用 Professional Profile 模板：渐变页头、编号章节、技能分栏与经历卡片；预览和编辑共用布局，不再切换为纯文本样式。
- 项目卡片除日期范围外，还参考标题后接概述/简介/技术栈的结构识别无日期项目；同一项目的副标题不会另开卡片。概述、技术栈及实现要点按字段对齐。
- 项目内 PDF 硬换行仅在展示时合并；保留原始段落用于保存，只有用户实际编辑的段落才替换。未知英文词边界采用保守空格，不擅自补写词语。
- 安全字段边界：只有行首明确的简历字段标题（含无冒号的独立标题）才分区，不按任意冒号、逗号或分号拆段。模型标签 `qwen2.5:0.5b`、URL、路径、代码及正文解释保留在原段落；未知标题不猜测，不额外切成小标题或技术标签。
- 导入简历支持排版页内逐段编辑、取消、保存和 PDF 导出；编辑只更新草稿，不覆盖原件。
- 当前不会自动恢复严重错序的 PDF 文本。后续语义结构识别必须保留内容溯源与完整性校验，不能编造或删除事实。

## 混合文本与长段落

- 原文与已确认补充经历共用排版器：识别 Markdown 章节/项目以及“代表项目”，避免补充内容落入上一份工作经历。
- 保留 `·` 项目符号边界，只合并段内 PDF 续行；模型返回的旧布局也要经过显式边界细分。
- 技能按原文类别排成全宽标签/正文行，不再把未知分组挤在半宽列里；明确的表格续行和字母间隔噪声只在展示层修复。
- 连续相同字段共享标题，例如只显示一次“项目特点”，全部原有要点仍可查看与编辑。禁止通过隐藏条目或省略数字来压缩版面。
- 新上传项目的生成指令鼓励合并成 3–5 条贡献与 2–3 条改进；证据清洗不再按 120 字符切断叙述。已被截断的历史内容需要重新读取材料，不能猜测补全。
- 每个展示块仍携带原文字串，未编辑保存必须与导入文本逐字符一致。
