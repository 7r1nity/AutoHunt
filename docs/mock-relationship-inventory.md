# 模拟站：雇主与客户关系岗位库

2026-10-10 批次 `autohunt-employer-client-20261010-v1`，追加 5,760 个岗位，覆盖 40 个行业、240 个岗位方向、24 个城市、52 个模拟招聘方，税前月薪区间 4–80K。包含实习、校招及不同经验等级。

## 数据特点

- 公司包括「外企德科数字技术（模拟）」「外企德科人力资源服务（模拟）」及虚构的人力资源、人才服务、行业企业；技术岗位包含华为客户场景与仅要求相关产品经验的对照岗位。
- 不使用“外包”“第三方”作为可见标签；用合同主体、办公地点、汇报关系、薪酬社保、项目周期等自然线索表达。公司和每条 JD 保留模拟声明，不代表任何真实企业正在招聘。
- 八种情形各 720 个：客户项目合同、仅有客户园区、双线管理、仅协助招聘、自有团队、品牌技术经验、关系未说明、固定周期项目。
- 关系有可核对依据的客户项目 2,160 个、自有/直接签约 2,160 个，信息不足 1,440 个。人力资源公司可以招聘自有员工；参与知名客户项目或熟悉其产品不等于该企业直聘。
- 824 个实习岗位分别包含有留任评估机会 277 个、无后续留任安排 276 个、未说明 271 个。有机会不等于保证录用。
- `autohunt_inventory_metadata` 是本机 SQLite 的独立盘点表，记录场景和可核对依据，不在 `jobs` 的公开字段中。现有 `JobOut` 不序列化该表，Agent 不应使用隐藏标签筛选。信息不足时应回答“未知”，不能凭公司名猜测。

## 生成与追加

```powershell
$env:PYTHONUTF8 = '1'
python scripts/mock_relationship_inventory.py
python scripts/mock_relationship_inventory.py --database C:/job_agent/job_site.db
```

不传数据库只打印生成汇总。指定数据库后先生成一致性备份到本地忽略目录 `.runlogs/mock-inventory-backups`，再用事务追加；批次台账防止重复插入。创建与公司一致的模拟招聘方账号，不改已有账号、岗位、简历、消息或申请。账号邮箱使用不可投递的 `example.invalid` 域。不要提交数据库、备份或历史记录。

模拟站按请求查询数据库，运行中无需因追加数据重启；已打开的列表需要重新加载。脚本不启动招聘搜索、沟通或投递，也不修改 AutoHunt 已保存的结果/统计。它不是已恢复的自动化测试套件，生成数据不代表筛选准确率已经达标。
