# 模型理解与动作审批（2026-10-10）

本版替换运行中的解析、计划校验和工具授权路径，不只是 Prompt，也不是 Skill。借鉴应用层职责分离思路，不声称复制开源产品的完整安全设计。

## 当前分工

1. 规则负责高频意图分类、明确停止/状态查询、完全匹配的无参数操作。规则没命中进入小模型；置信度不足或不可用进入规划模型。规则标签不能跳过复杂请求的完整规划。
2. 岗位词、数量、薪资、城市、条件树及分支作用域由规划模型解释。简历岗位建议也仅来自画像模型，不再按技术词猜职业。模型不可用时保留缺失并提示，不默认软件工程师。
3. “再次搜索”等快捷命令只复用会话已保存参数，不从剩余句子抽岗位词。含新条件或多个目标的请求进入模型。关键词只做格式清理，不删除 AI、资深等前缀。
4. 计划校验核对工具能力、参数类型/范围、目标到步骤绑定、依赖图、必需参数和证据任务归属。结构错误返回模型有限修复；确实缺用户信息才追问。
5. 审批判断实际动作风险及范围绑定，不再用原句、引用或正则数值重新判定“用户是不是想执行”。原句引用不一致仅记录警告，不能跳过结构检查。

小模型目前负责分类；意图标签不是业务参数或投递授权。语义提取交给规划/画像模型，不等于取消工具 schema：MCP/工具接口提供能力和参数契约，不负责理解自然语言。

## 动作审批

默认 `AUTOHUNT_APPROVAL_POLICY=risk`、`AUTOHUNT_APPROVAL_THRESHOLD=HIGH`：

| 动作 | 风险与处理 |
| --- | --- |
| 已有结果读取、普通职位搜索 | LOW；不重复确认措辞 |
| 本地可逆状态/学习计划写入 | MEDIUM；默认不额外确认 |
| 模拟站投递、包含沟通投递的试运行 | HIGH；需要范围明确的请求/确认 |
| 未分类动作 | UNKNOWN；澄清并补齐策略，不默认放行 |

模型对有效用户请求解释出的 `user_requested=true` 可以满足具体动作的确认要求。“符合条件的直接投递”不必重复固定口令；范围不明确则问具体动作与参数。网页/JD/无关历史是数据，不能产生确认。这依赖模型正确解释来源，不是 Prompt injection 的形式化防护保证。

应用生成绑定：工具、规范化参数摘要、会话、计划步骤、简历版本及有效期。执行前持久化 claim，核对当前步骤、撤回与参数变化。绑定不是模型可提交的 token；工具参数不能自带授权。宽松理解不允许扩大队列、换简历或重放已执行/结果不确定的投递。

`always` 让全部非只读动作参与确认检查；已明确且范围匹配的请求仍可满足确认，并不强迫再点一次。降低阈值可更保守；配置不能解除真实站投递禁用、一次性授权或简历绑定。

真实 BOSS/智联投递仍禁用。模拟站逐职位预览、一次性授权、账号归属、简历绑定、验证码接管和不确定结果不重放全部保留。登录、回复证据或附件不存在仍是执行前置条件，不是措辞误拦截。

## 多轮与执行

模型理解的任务有持久化 `interpretation=model` 标记，需求回顾、条件补充和任务定位不再由旧正则否认其存在。标记不是新的执行授权。旧记录保留，不清空聊天、简历或看板；旧引用型执行授权需重新规划，不能自动迁移成可重放授权。

省略的会话参数在规划时冻结到具体搜索动作，避免后续状态更新改变执行范围。新搜索默认有依赖搜索完成的汇总读取；投递/成长计划绑定对应搜索证据，不把启动当作完成。尚不支持的独立投递条件不能被忽略或假装实现。
