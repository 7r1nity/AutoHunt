# 会话上下文管理

## 2026-10-09：统一输入角色、任务记忆与上下文装配

本轮不是单句补丁：`runtime/understanding.py` 区分任务命令、参数更新、回顾、指代、确认、拒绝与未解析输入；不授予工具权限。共用既有搜索/动作语义，高频完整规则仍不调用模型，未知语义继续规则 → 小模型 → 主模型处理。

`runtime/memory_context.py` 为路由、规划与主模型提供同一事实投影。任务恢复后才组装路由上下文；原始任务、最新条件、追问来源/TTL、撤回动作与对象稳定ID优先，长报告/轨迹/快照预览先让出预算。主模型保留原任务全文；小模型使用有明确省略标记和来源ID的分类投影，不再在客户端直接截断JSON。关键状态仍超预算则明确停止，保留原数据，不静默丢失要求。

任务记忆独立于执行计划和近期聊天：规则快路径与复杂规划均捕获 `task_request`；新独立任务换锚点，追问/回顾不换锚点。已验证修改仅更新对应字段，保留原文、补充来源和根任务ID；未执行失败任务续接时携带已验证补充。取消/拒绝只撤回执行与当前追问，不清空会话条件、对象或原始历史；只有明确重置命令清除临时状态。回复已返回、规划成功、执行成功是不同状态，不再把规划失败回复的成功返回记成原任务完成。

普通搜索槽位同步不重写未回答的问题和有效期；真正填入缺失字段才消除追问。新的明确动作、已知只读查询和纯问号不被旧待补问题吞掉。澄清标签缓存绑定会话、任务、焦点和条件，不能让同一句“那个呢”跨任务沿用旧标签。

模型规划可提交数值 `slot_evidence`（仅 result_limit / salary_min / max_jobs），代码核对连续用户原文、字段语义、数值与单位。它解决“模型理解了工资底线一万五，但校验误当猜测”的接口缺口；工资中等、年/日薪混用、匹配分当薪资、多个冲突数值仍不猜测。规则已验证的字段优先；引用不授予动作权限。

已验证参数另存为 `condition_overrides`，不依赖近期补充文本是否仍在窗口里；解析优先级为原请求 → 旧补充 → 最新已验证字段 → 本轮明确修改。本轮经核对的模型数值引用可更新旧规则值，不能由较早的补充重新覆盖。

`revoked_tools` 独立保存已撤回动作，不随近期答案截短消失。恢复任务、后台计划持久化都保留撤回事实；计划执行与工具授权再次检查，尚未开始的动作被阻止，已执行或已进入外部请求的动作不能承诺撤销。真实站投递仍禁用，模拟站预览/一次性授权/简历绑定/验证码接管/不确定结果保护未取消。

核验：新增98项临时隔离诊断，含10个行业多轮链路、大报告、槽位来源、取消保留条件、参数引用、连续参数更新优先级、混合否定/假设引用、后台排队撤回、失败→更新→续接、SQLite生命周期及澄清缓存隔离；既有292、34、16项复测通过。5条配置模型的合成规划样例最终通过，其中1条是上下文确定性快路径；真实模型复测曾发现参数校验误拦截，以及把其他动作的否定带入肯定命令引用，均修复并再次复测，不是忽略失败。所有规划均未调用真实招聘执行器，未发送个人简历。Python语法/前端类型检查另行核验。

依用户要求未恢复仓库常驻自动化测试套件；下文旧 `agent/tests/*` 路径和历史测试说明均为归档，不是当前可运行覆盖。上述诊断不证明所有开放语义、长周期真实使用或浏览器端到端均已通过，也未新增向量语义记忆或模型置信度校准。

## 归档说明（2026-10-08）

2026-10-08：通用多目标请求、缺槽语义补充、逐步依赖状态与恢复见 [编排 Review](intent-orchestration-review.md)。`instruction_request` 保存完整目标、原话与参数补充；`tasks.plan_id` 控制当前后续动作归属。历史条件继续保留，独立动作授权过期不清空上下文。

## 状态分层与优先级

当前用户明确指令 → 本会话已验证条件/追问/引用对象 → 当前主简历与已确认长期偏好 → 最近历史 → 精简轨迹/显式检索的历史。

`session_search_state` 是条件数据的单一来源。`session_dialogue_state` 是会话级 DST（Dialogue State Tracking）：

- `active_intent`：search / applications / resume / learning / general。它是当前业务焦点，不是工具执行授权。
- `frames`：各业务槽位、字段来源、最近追问、待补槽位。只改明确字段，不覆盖未提及字段。追问支持「15个」「14k」等单槽短回答；其他语义省略由主模型结合 DST 处理。
- `snapshots`：实际展示过的职位、简历条目、计划及稳定 ID、顺序、来源、版本。工具读取但尚未展示的列表不能直接作为用户审核对象。
- `pending`：真实待确认动作、规范化参数、依赖版本、TTL、单次领取状态。聊天里口头说「建议做 X」不会自动变成待办或执行许可。
- `tasks`：本会话所属的浏览器/投递任务 ID。共享浏览器串行锁与会话任务归属是两个不同约束；不能操纵其他会话的任务。
- `trace/summary`：有来源的请求、工具结果、条件变更、确认、拒绝轨迹。旧轨迹按可观察事件抽取压缩，**不是模型编造的事实摘要**。聊天与执行事件的原始去敏历史另外保留。

简历、长期求职偏好与职位库仍是单用户共享的持久化数据；临时上下文按会话隔离。并未实现多租户账户隔离。

## 上下文保留与动作生命周期

1. 明确重置：发送「重置上下文」「清空会话状态」「重新开始」，或点击运行面板的「重置临时上下文」。清除焦点、待办、引用与临时条件，从当前简历/已确认偏好重新建立基线。不会删除简历、看板、原始历史或正在执行的外部任务。需要停止浏览器任务时使用「停止搜索」。
2. 空闲不清理：会话条件、焦点、已展示职位和交互历史持续保留；新消息只更新明确字段，不因 15 分钟或服务重启清空数量、薪资、城市。明确重置仍可从主简历重新建立基线。待确认动作/追问有各自有效期，过期仅失去执行权限，不授予历史新的授权。
3. 距离衰减：模型上下文仍按预算装配最近历史和精简轨迹，旧原文可以按需检索；轨迹展示权重为 `0.8 ** 轮次距离`。审核等写操作引用限制为最近 6 轮、30 分钟；追问与待办限制为最近 4 轮、10 分钟。只读职位详情可引用本会话已展示列表，不受空闲期限影响；过期焦点标为只读。**这是上下文装配优先级，不是修改模型内部 attention 权重，也不是删除持久状态。**

待办被拒绝后不能由模糊确认复活；「算了」退出待办，条件和历史保留（2026-10-09更新）。没有待确认动作时，「取消」「算了」「退出当前任务」也会停止当前会话所属的活动搜索，不停止其他会话的浏览器任务。已领取的动作无论成功、失败或结果不确定都不能重放。服务在领取后崩溃时保留 claimed 状态，需要重新明确发起，不自动恢复副作用。

## 意图与执行

规则命中且完整消耗输入 → 快速执行高频只读查询或明确的搜索/参数调整。

规则未命中 → 小模型分类（携带紧凑 DST） → 高置信度且安全的确定性处理，或交给主模型进行参数/指代推理与原生工具调用。小模型低置信度、错误、超时或副作用候选区分度不足都向主模型降级；主模型仍受统一工具安全策略约束。

P0 安全拦截位于所有快路径之前。大模型不是绕过权限或执行未知工具的兜底。

新增高层工具：

| 工具 | 作用 | 边界 |
|---|---|---|
| context_state_read | 读取结构化 DST | 只读 |
| context_history_read | 检索本会话历史并返回消息/运行 ID | 按关键词、有限结果；不是当前授权 |
| context_reference_resolve | 前五个/第二个/名称 → 已展示对象 | 同话题、有效期、版本与序号校验；歧义拒绝猜测 |
| context_question_ask | 记录最近问题和缺失槽位 | 不写长期偏好、不启动浏览器 |
| context_action_propose | 注册待确认的规范化方案 | 只允许搜索、生成学习计划、生成简历 Diff；参数按目标工具 schema 校验 |
| job_review_selection | 审核已展示的职位子集 | 本地标记，不沟通、不投递；全批事务核对来源、薪资、JD 与阶段 |

「行吧，那就照你说的办」只消费当前唯一、未过期且依赖条件未变化的待办；否则简短询问具体操作。提出搜索后的自动沟通/投递（dry_run）不能偷渡到通用搜索确认中。

「我觉得前五个不错，可以通过审核」指向实际展示的快照顺序，不按数据库后来重新排序的结果挑选。成功后看板标为「审核通过 · 待授权」，仍保留在 review 阶段；沟通、简历发送继续走独立预览/授权流程。职位重要事实改变后本地审核标记失效。

## 压缩、检索与信任边界

主模型结构化状态、临时条件、当前画像、简历对象、所属任务、公开记忆分别分配字符预算；超长工具返回保持合法 JSON 并标注省略，必要时重新缩小读取范围。原生 assistant/tool_call_id/Observation 组不能拆坏。当前请求和调用参数不被静默截断；无法满足总预算时明确停止并保留检查点。

历史检索仅按本会话具体关键词检索、限制结果数量并保留来源；目前不是向量语义检索。历史、简历、公开记忆、JD 和工具返回都作为数据处理，不授予工具权限。模型输出的「已修改」等自由文本不更新 DST 事实，只有实际工具结果/明确条件写入可更新。

## 持久化与可观测性

SQLite 原子 read-modify-write 更新 DST，避免后台状态监测覆盖前台新焦点。待办领取先持久化再执行。只读工具循环检查点保留原生调用关系与简历/条件依赖；恢复时依赖变化不沿用旧上下文执行，而要求重新发起。写入/外部结果不确定不自动重试。

接口（沿用 API 认证和 Next.js 同源代理）：

- `GET /api/v1/conversations/{id}/context`：DST、只读/有效焦点、参数基线、保留策略和空闲时长。
- `POST /api/v1/conversations/{id}/context/reset`：重置临时上下文，与会话请求互斥；正在处理时 409。
- 运行面板「上下文状态」查看激活任务、待补参数、待确认动作、精简轨迹和来源。
- 运行步骤包含 dialogue_state、实际 tool_started/tool_finished/denied 与确认轨迹。完整历史仍可在所属会话查看。

## 评估闭环与交付边界

浏览器窗口/登录配置跨会话共享，任务控制仍归属发起会话。`browser_task_read` 将共享可用性与任务权限分开：所有会话可读取 `can_start_search/shared_browser_busy`，其他会话的任务 ID、查询、URL 和结果不返回。已完成/失败/停止的旧任务不占用浏览器；无存活 worker 的非终态记录在下一次启动时安全结束，不仅凭数据库历史状态拒绝搜索。存活 worker（含等待人工与 finally 清理）仍阻止重入，OS 浏览器锁继续保护搜索/投递互斥。继续、暂停、停止操作必须通过原会话归属检查；空简历/缺少岗位依然在创建任务之前澄清。

搜索前校验：没有明确岗位且当前简历/偏好/有效会话不能提供方向时，登记 `queries` 缺槽并提示上传或启用简历、或明确目标岗位；不启动浏览器，不使用任何默认行业词。规则快路径、LLM 原生工具、试运行及直接搜索 API 均有门控。模型参数不是用户意图的证据：没有基线时不能给泛化“帮我找工作”凭空填入岗位。明确指定岗位可以在没有简历时搜索，不意味着已做简历匹配。未知行业的简历解析也不默认写入软件工程师。追问后简短岗位回答可填入会话方向，再由明确搜索命令启动。

离线测试见 `agent/tests/test_dialogue_context.py`，配合原有搜索/路由/运行/安全测试。使用测试替身，不发送真实简历、凭据或消息到模型/招聘网站。

每次改动至少检查：条件继承与隔离、话题切换、同名歧义、序号范围、未展示对象、TTL/轮次距离、旧版本、拒绝与重复确认、崩溃后的 claimed、原子更新、检索隔离、合法 JSON/原生协议、隐私脱敏、复杂搜索降级、快路径模型调用次数。

硬性标准：未授权外部写入=0；陈旧/歧义对象误执行=0；拒绝后复活=0；串会话控制=0；简单规则命令模型调用=0；回归测试无失败。

## 报告、序号追问与统计闭环

搜索候选链接数不是最终符合条件的数量：`result_limit` 限制核实合格的唯一职位，`max_jobs` 限制读取预算，数量上限和薪资过滤在落库前再次校验。重复启动沿用持久会话条件，不因空闲改为不限数量/薪资/城市。

`search_report` 与运行摘要使用同一份数据与格式，先汇总本轮已读薪资、招聘类型、福利和 JD 原文证据，再列出全部已记录职位的简短编号摘要（不再仅选前三个）。职责/任职要求按标题段落提取，不截取 JD 开头的模拟声明；无法提取时明确说明，没有用模型编造职责。月薪参考为可识别月薪区间下限的范围与中位数，不冒充真实录用薪资。此版是可追溯的抽取式报告，不是深度职业市场预测。

报告展示时持久化有序职位快照（最多 200 条，对齐读取预算）。「我想详细了解一下第8个」按快照稳定 ID 读取完整已保存 JD 与原始链接，不按看板新排序，也不启动浏览器/投递。该只读查询不会延长旧投递授权；序号越界、未展示列表或缺失职位不猜测。

单职位焦点 `selected_job` 独立于整张列表：如「第24个不错」只建立只读焦点，不审核或投递。「给我链接」「给我它的链接」沿用同一个职位；公司名称按已展示对象匹配，同名时简短澄清，列表行号绝不当作数据库 ID。焦点跨空闲和重启保留；明确展示新列表或重置上下文时取消旧选择。模型内部重读的未展示列表不替换焦点，不自动追加整张列表。显式查看列表时仅输出一份代码生成的规范列表；链接/详情工具的事实直接展示，不再由模型二次改写。链接以可点击 Markdown 展示，链接请求只输出该职位基本信息和入口，完整 JD 在明确追问时提供。

`agent/tests/test_job_followups.py` 覆盖报告第24行≠数据库id24、选择→链接→公司指代、内部重排、空闲/重启、歧义、越界、重复列表抑制、模型 ID 替换和兴趣不授予审核权限；隔离 UI 测试实际点击链接并验证新标签地址，不访问真实招聘网站。

当前简历统计同时纳入 completed / stopped / failed 任务已记录的唯一职位，去重累计；尚未读取的候选不能进入 JD 分析，旧简历不混入。统计提供城市、薪资、跨行业技能、招聘类型、福利与整体 JD 画像，并标注部分完成任务数。前端收到 browser_summary 或轮询到任意搜索终态后刷新统计，原生运行任务不再被旧完成回调排除。后端不依赖模型回复来更新统计。

回归闭环：`agent/tests/test_search_report_flow.py` 覆盖隔一天重复搜索仍保留15个/12k/四城、150个候选不能新增超过15个合格职位、跨行业JD提取、报告全量序号、看板重排不改变第8个、空闲只读仍有效但审核/确认过期、部分统计和报告幂等。`agent/tests/test_search_statistics_ui.py` 全量拦截 API，用隔离浏览器验证 SSE 摘要自动刷新统计、统计页面整体 JD 与详情链接；设 `AUTOHUNT_CHAT_UI=1` 运行，不向真实网站发送任何动作。

配置真实模型后的补充验收：用跨行业多轮样例测意图/槽位准确率、指代解析正确率、必要澄清率、工具选择准确率，以及模型调用数与 P50/P95 延迟；错误回放到 fixture 与回归用例。先在模拟招聘网站观察真实 UI/网络/人工验证码接管，再对真实平台只读测试；真实投递另行授权。

测试替身验证的是状态、安全与工具协议，**不能证明真实模型对所有语义省略都理解正确**。这版没有新增 embedding 语义记忆、LLM 历史摘要或模型置信度校准；下一步应依据误解样例决定是否需要，而不是用更多历史掩盖参数/授权问题。
