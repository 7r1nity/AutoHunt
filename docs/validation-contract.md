# 请求校验契约

校验不负责替用户猜条件，也不把内部规划错误变成用户的口令测试。所有规则快路径、上下文补参和模型计划仍经同一个工具授权策略；真实网站投递保持关闭。

## 决策分类

| 分类 | 例子 | 处理 |
|---|---|---|
| `repair`：候选计划错误 | 漏目标、步骤 ID/依赖错误、引用不实、整句关键词、字段类型/范围不符合工具契约、已填参数仍被追问 | 先确定性规范化；仍不通过时最多一次无工具语义修正，重新核对完整请求 |
| `clarify`：真实用户信息不足 | 无简历且无岗位词、模糊薪资、缺投递分数、冲突条件、不支持的过滤能力 | 保留完整请求和条件，只追问缺失或冲突项；不执行半条复合命令 |
| `block`：权限或风险边界 | 否定/引用/假设不构成授权、撤销授权、过期或简历变更、未授权试运行 | 不通过模型修复授权，不调用执行工具 |

语义修正后仍失败属于内部规划失败：保留原请求，停止执行，记录 `repair_exhausted`。不能解释成用户必须重复“生成学习计划”等固定口令，也不能为了通过校验放宽薪资、匹配分或投递权限。

## 校验路径

搜索授权使用 `parse_search_message` 的同一命令语法，规划层不能再用独立口令表拒绝“给我找工作”等已识别的明确请求。岗位条件的否定与动作否定分开：“帮我找工作，不要外包”授权搜索并保留负向筛选；“帮我找工作，不要搜索”撤销该搜索。校验完整来源语境，不能从否定、询问或引用中截取一个正向短句来获得授权。授权搜索不授权投递；模型仍须完整解析筛选条件，事实不足仍需核实。

独立“20个左右”按20个结果目标记录，不与薪资、匹配分、经验年数或“20个城市”混淆。“可以有实习”只是允许包含，不等于必须只找实习。这些规则/提示不保证模型端规划和岗位语义判断始终正确；本地契约验证与真实模型/网页验收分开记录。

1. 有效请求来源：当前消息，以及仍有效的原请求和补充。历史、简历、JD、模型回复是数据，不是动作授权。旧待补请求不会阻止一条独立的新请求。
2. 结构预检：一起记录引用、目标绑定、未知工具、重复 ID、依赖错误等问题，不要求用户修正 JSON 或工具名。
3. 来源驱动规范化：数量/薪资/城市由明确原文和会话状态核对；数字字符串仅做无损编码转换，之后仍验证证据。先按动作收窄条件范围，再检查分数与薪资，不能把成长计划条件搬到搜索或投递。已核实槽位不再保留旧 `missing_slots`。
4. 依赖和权限：结果读取、统计、投递、计划绑定前置搜索的实际任务 ID；间接依赖支持最近的唯一结果生产者，多个并行来源不猜测。引用只读/否定的投递状态，不等于授权开始投递。
5. 有界内部修正：最多一次 JSON/schema 修正、一次语义修正，总计最多三次规划调用，共享原来的 60 秒总预算。候选 JSON 只是待修正的数据，不是新授权。取消/超时会取消并等待规划子任务，不遗留执行器。
6. 执行前再次授权：规范化后的精确参数、用户命令、简历版本、计划归属和有效期再次核对。模拟站继续保留逐职位预览、一次性授权、验证码接管、不确定结果不重试；修正规划不能重放已执行步骤。

独立搜索总结可补齐一个来源明确的只读步骤；不能用总体总结覆盖用户另要的过滤列表。分析不足的总结归属于成长计划，不凭“总结”二字强制增加另一个搜索结果目标。

## 续接与引用来源

“重新开始任务”或明确“按原请求重新执行，其他步骤也要完成”是任务引用，不是新的任务定义。未执行请求可以在确认浏览器归属、简历版本和请求年龄后重新规划完整目标；已执行、终态或结果不确定的任务不可按此路径重放。

旧版本可能把一次重试指令保存成独立待澄清请求。它不能覆盖持久化的原任务：续接解析器和待补回答均先核对两者的来源绑定；模型视图中旧的引用追问标记为已被替代，但不删除会话历史。已经绑定的续接不能由模型输出的 `continuation=false` 解除。模型把重试句用作工具引用时，仅恢复原任务中该工具唯一、明确的动作引用；不存在或有多个候选时不会猜测。

引用格式仅允许恢复连续空白的差异（例如模型把两个空格抄成一个）。恢复后保存实际原文片段并重新授权校验；不得修改数字、单位、否定词或标点，不拼接不连续片段，不接纳无关历史。`invalid_citation` 记录具体字段位置，便于区分任务来源错误与引用格式错误。

## 可观测性和验证边界

### 停止契约

页面通用“停止”、运行面板“停止当前会话”及完整的“中断 / 停止任务 / 停止自动投递”等命令都使用同一个停止入口。普通命令只作用于当前会话；“停止全部任务 / 取消所有投递”覆盖所有会话。停止入口不经过模型或会话执行锁，也不因原对话已经完成而忽略后台投递队列。

先持久化撤销队列并阻止目标会话派发，再取消并等待正在派发的操作、搜索和投递执行器，最后核验队列与运行状态。取消的队列不会被延迟回调或失败恢复重开；断开 HTTP/事件流不撤销后台清理。前端核验最终结果后才显示已停止；超时/异常返回未确认，而不是假成功。停止默认会话或全部会话还关闭默认会话拥有的每日搜索与自动投递开关，避免定时任务再次启动，需用户重新开启。

已发送消息、已确认投递和历史保留；发送途中被中断仍标记结果待核验，不能撤回或自动重投。明确标为“停止搜索”的搜索卡片仅停止搜索；单个运行的低层取消 API 仍为定向操作，不代表停止整批任务。

前端「任务与上下文 → 执行步骤」展示 `plan_validation` 决策、问题代码/字段，以及 `plan_repair` 修正阶段。后端同样保存这些运行事件；`plan_failed` 保留具体校验代码，而不是全部归为 `planning_rejected`。没有调用招聘工具的规划失败与真实执行失败保持区分。

按项目约定不恢复已删除的自动化测试源码。本次使用隔离、内存中的契约断言（含模拟模型故障、授权二次校验、超时/取消）和当前配置模型的无工具规划，覆盖金融、外贸、医药、制造、会计、护理、设计、人力资源等方向；这些诊断不启动搜索、不沟通、不投递、不修改历史。Python 语法和前端类型检查另行执行。

这不是永久自动回归覆盖，也不是浏览器端到端验收，更不能保证任意自然语言永不出现解析错误。模型、工具能力或授权规则变更后，仍需重新验证来源归属、漏目标率、误澄清率和权限拒绝率；不能把“所有请求都能通过”当正确性指标。
