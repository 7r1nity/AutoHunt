## 1. 目标架构

### 1.1 唯一判定入口（新增 `core/input_intent.py`）

```python
class InputKind(StrEnum):
    COMMAND     = "command"       # 可执行指令
    QUESTION    = "question"      # 疑问句（询问）
    MENTION     = "mention"       # 引用/转述他人指令
    RETRACTED   = "retracted"     # 命令后被撤回（"但先别搜索"）
    CONDITIONAL = "conditional"   # 条件从句限定指令（"如果是实习必须有转正机会"）

@dataclass(frozen=True)
class InputVerdict:
    kind: InputKind
    executable: bool                      # 是否允许执行该指令
    command_span: tuple[int, int] | None  # 指令在原文中的位置（供 grounding 使用）
    reasons: tuple[str, ...]              # 命中的判定依据，用于可解释性

def judge_input(text: str) -> InputVerdict: ...
```

**关键设计决策：调用方只能消费 `executable`。**

不允许调用方自行在 `conditional` 与 `command` 之间做选择——那正是本次缺陷的成因（`search_language` 与 `planning` 对同一句话给出了不同答案）。

### 1.2 判定顺序（固定，且必须写进测试）

```
1. 安全类（P0）：注入、密钥、越权路径        → 独立于本判定，优先
2. 撤回/否定：命令前否定 或 命令后撤回        → RETRACTED, executable=False
3. 引用：引号包裹**指令本身**（非取值）        → MENTION, executable=False
4. 疑问：疑问词/问号作用于**请求本身**        → QUESTION, executable=False
5. 条件：条件从句限定**指令**（非条件取值）    → CONDITIONAL, executable=False
6. 否则                                       → COMMAND, executable=True
```

**核心原则（P0 已验证）**：**标记的位置决定语义，而非标记的存在**。

| 情形 | 判定 | 例 |
|---|---|---|
引号内是**取值** | COMMAND | `帮我找软件工程师岗位，JD包含‘海外市场’` |
引号内是**指令** | MENTION | `他说“帮我投递简历”，这句话是什么意思` |
条件限定**取值** | COMMAND | `帮我找软件工程师岗位，如果是实习必须有转正机会` |
条件限定**指令**（开头/后果疑问） | CONDITIONAL | `如果我说帮我找算法工程师，你会怎么做` |
疑问词落在**命令之后的条件里** | COMMAND | `帮我找软件工程师岗位，岗位职责需要分析为什么客户流失` |
疑问词落在**请求本身** | QUESTION | `怎么搜索算法工程师` |
命令后撤回 | RETRACTED | `帮我找软件工程师，但先别搜索` |
命令前否定 | RETRACTED | `不要搜索算法工程师` |

### 2.4 防复发机制

**规则**：产品代码中禁止新增本地判定正则。

```
允许存在判定正则的文件：core/input_intent.py
禁止：app/**/*.py 出现 §0.1 表中那 6 类模式的**新增**副本
```

**实现**：在 `agent/evaluation` 加一条 lint 用例，维护已知守卫模式清单（引号类、条件类、疑问类、否定/撤回类），扫描时**容差**现有副本（记录技术债），新增副本即失败。

容差清单随 P1 逐步缩减至 0，缩减完成即删除容差。

## 3. P2 数值解析器重构

### 3.1 缺陷

```
输入：帮我找工作 薪资十五千以上
期望：15000        实际：5010
```

**根因是累加器结构**：`十` 被立即结算进 `section`，之后 `五` 遇到 `千` 时只剩 `5 * 1000`。

第一次尝试（只改省略式条件）**无效**，因为问题不在省略式判定，而在 `十` 的提前结算。

### 3.2 正确算法

```python
pending = 0   # 尚未与更高单位相乘的累计（"十五千" 里的 15）
digit   = 0   # 当前个位
for ch in text:
    if ch 是数字:            digit = 值
    elif ch in 十/百/千:      pending += (digit or 1) * 单位;  digit = 0
    elif ch == 万:           total += (pending + digit) * 10000;  pending = digit = 0
结果 = total + pending + digit
```

**口语省略式**（`一万五` = 15000）单独处理，且**仅当**数词以"单位+裸数字"结尾时生效——这正是 `十五千` 不该触发它的原因。

### 3.3 语料

见 `agent/evaluation/corpus/numeral_cases.json`（本次新增，纯数据）。

当前基准中中文数字只有 **1 条**用例，这是该缺陷长期未被发现的原因。
