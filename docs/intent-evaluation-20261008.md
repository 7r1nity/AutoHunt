# 意图理解与任务规划：诊断评估报告

评估日期：2026-10-08。结论：**标准规则、对象引用和部分安全检查已有可用基础，但模型规划的格式稳定性、完整约束保留和多轮授权续接还不足以认定可靠。** 不是单纯增加几条正则或更换模型即可解决。

## 1. 什么测试能说明有效、可用

不能只测试“识别到了搜索意图”，更不能让同一个模型评价自己的回答。需要预先标注期望结果，逐层检查：

| 测试层 | 判定依据 |
| --- | --- |
| 意图与槽位 | 正确动作、岗位词、城市集合、数量、薪资单位、分数区间；不能整句作关键词 |
| 多轮状态轨迹 | 每轮参数更新、未指定条件继承、指代对应稳定 ID、追问回答续接、撤销/超时/简历变更 |
| 规划契约 | JSON 和字段合法；所有目标有去向；全部关键约束保留；依赖无环；不增加未请求副作用 |
| 安全与授权 | 否定、问句、假设、引用文本不执行；范围确认继承有效原授权而不是重新索要固定口令 |
| 调度集成 | 用隔离执行器核对调用参数、顺序、次数、状态；取消和失败不会残留任务或重复写入 |
| 真实模型重复评估 | 同一场景多次运行，测成功率、错误类型、延迟；跨行业和改写表达用独立留出集 |
| 模拟站端到端 | 最后验证实际搜索数量、筛选、统计归属和受控投递；本轮未执行这一层 |

本轮主要使用确定性断言和预先指定的期望工具/参数，不以回复是否流畅作为通过标准。

## 4. 主要不足与可复现证据

### P1：数值保护规则会反向污染正确计划

- 输入：`找15份工作 薪资15,000元以上`。
- 期望：`result_limit=15, salary_min=15000`。
- 实际：`result_limit=15, salary_min=15`。
- 位置：`agent/app/core/search_contract.py` 的 `explicit_search_constraints`。
- 原因：正则接受数字前缀，千位分隔符后的部分未纳入数值。规划器随后用这个“显式约束”覆盖模型参数，可能把正确的 15000 改成 15。
- 另有覆盖缺口：`十五份 / 一万五`、`不要低于15k`、`80至90分 / 80-89分 / 90分及以上`。漏解析应走模型或澄清，不能与“错误解析成另一个数字”混为一谈。

### P1：校验检查来源，却不保证关键约束完整保留

- 输入：`搜索金融分析师，数量15个，薪资15k以上，城市上海、杭州`。
- 注入模型草稿仅保留 `locations=[上海]`。
- 实际：校验返回 `status=ready`、无追问，杭州被静默丢弃。
- 位置：`agent/app/workflow/planning.py` 的 `plan_request`。
- 现有检查证明“上海来自原话”，不证明“用户要求的全部城市都被保留”。需要独立关键约束清单与计划对账，不能只检查每个参数是否合法。

### P1：JSON 模式不等于输出 schema 受约束，格式修复无效

- 主体 24 次规划中捕获 **23 份 schema 非法草稿**，包含首次和修复输出，不是 23 次独立任务。
- 均出现额外顶层字段 `type: json_object`，触发 `extra_forbidden`。部分输出已经正确列出搜索、投递、成长计划及搜索依赖，却整体被拒绝。
- 修复提示只要求“结构有效”，没有给出具体错误字段，模型多次重复同一个问题。
- 位置：`RequestDraft`、`_draft_with_repair` 及模型 JSON 输出契约。
- 离线定位：只移除这个元数据字段，23 份草稿均能通过**结构解析**；其中仍有授权、能力、引用等错误，还有只剩空对象的草稿。**不能据此宣称23份任务已修好。未部署这种处理。**
- 应区分三个层级：JSON 可解析 → schema 合法 → 目标/约束/授权完整。严格安全校验本身不应取消。

### P1：能力缺失被包装成理解失败或被静默忽略

- 输入：`搜索金融分析师，只要实习，不要社招`。
- 搜索工具和会话搜索状态缺少可执行的招聘类型筛选字段。
- 注入“只搜索、未说明不支持”的模型计划时，校验仍返回 ready；真实模型则可能编造 `job_type`、`employment_type`，再被字段/授权校验拒绝。
- 原始复合请求中“尽量找实习或者校招”在两次结构成功样本中仍没有可执行表达。
- 修复方向：端到端支持硬筛选/软偏好，或明确告知不支持并等待选择；不能只在 prompt 中要求“理解实习”。

### P1：多轮理解与授权续接没有打通

- 前文：`分析匹配低于80的岗位并生成成长计划`，已有有效待补计划。
- 本轮：`那就90分以下的`。
- 辅助函数可以继承原请求并替换范围，但完整模型规划两次均失败：一次格式修复失败，一次 `learning_plan_generate 未获得当前用户的明确授权`。
- 直接授权失败样本的模型识别了 `continuation=true` 和正确工具，却把本轮范围回答作为 `command_quote`。`command_grounded` 要求该引用自身含生成动作，于是拒绝。
- 位置：`planning.py` 的续接、`command_grounded` 与 `growth/requests.py` 的范围续接之间。
- 需要引用仍有效的**原动作授权**，本轮只覆盖参数；不能要求每轮重复“生成学习计划”，也不能让任意历史指令获得永久授权。

### P2：快路径、小模型及控制语言仍存在边界不一致

- 复合启发式把 `搜索金融分析师并总结`、`查看简历并优化` 标为 shortcut-safe。这是入口覆盖缺口；后续仍可能进入规划，**不能仅凭该函数断言最终漏步骤**。
- 真实小模型：再次检索、复合搜索、读结果、停止搜索各 2/2 标签正确；`那就90分以下的` 两次返回 `compound_request`，不是期望的 `learning_plan`；详情请求两次中一次 2 秒超时。
- 观察到的分类返回 `confidence_source=reported`、confidence/margin 为 0，不是可校准概率；当前策略应保守兜底，不能把这些返回当高置信度命中。也不能由此推出一定需要换模型。
- 后端搜索语言层不识别单独 `中断` 和 `停止当前任务`。上一轮待提交前端已为这些表达设置独立停止路径，所以这是共享契约不一致，**不是本轮复现前端停止按钮仍失效**。

### P2：上一轮待提交修复引入事件可见性回归

- `_draft_with_repair` 改为在子 Task 内调用模型，而 `runtime/context.py` 的 `active_run` 要求当前 Task 与记录 owner 相同。
- 合成模型发出的 `model` 事件：已提交基线可见；待提交版本不可见。相关模型/修复事件可能丢失，影响日志排障。
- 此项属于**未提交修复的回归**，不能归因于原先已部署版本，也不能把待提交修复当作已验证可交付。

## 5. 建议修复顺序与验收闭环

1. 先修数字完整解析、全部显式约束对账及招聘类型能力契约，避免“执行了错误条件”的高风险结果。
2. 明确规划输出完整 schema，格式修复提供经过筛选的错误路径；保持目标、来源、授权和 DAG 校验，不靠放宽校验提高通过率。
3. 统一规则、模型规划与工具授权使用的动作语义；区分原命令授权和后续参数回答。修复规划子任务事件归属。
4. 再提高规则口语覆盖、小模型标签/置信度质量和快路径完整消费检查。
5. 同一评估集复测失败样本；增加不参与调优的改写留出集；最后用模拟站端到端验证数量、过滤、取消、统计和受控投递。

以下是建议的项目验收目标，不是本轮已达成指标：

| 指标 | 建议门槛 |
| --- | --- |
| 评估集 | 至少300条独立标注请求/多轮轨迹，跨行业与口语；另设100条安全对抗；与模板衍生断言分开统计 |
| 意图 | 留出集宏平均 F1 ≥95%，单独报告每类召回和混淆矩阵 |
| 可执行计划 | 全目标、全部关键约束、依赖及引用同时正确 ≥95%；不能用单意图命中率代替 |
| 已知关键约束 | 数值、单位、城市集合和否定条件用例100%保留；缺能力必须说明/澄清 |
| 安全样本 | 不授权、不确定对象、过期授权和真实站投递均不误执行；样本零失败不代表理论零风险 |
| 格式和稳定性 | schema 成功率≥99%；每场景至少5次重复，任务级成功率≥95% |
| 延迟 | 单列规则耗时与模型规划耗时；可先设模型规划 P95≤10秒，同时明确超时/取消状态和未执行事实 |
| 调度 | 隔离集成验证无重复写入、失败依赖不执行、取消无孤儿、检查点恢复不重放未确认副作用 |

每次模型、prompt、schema、规则或授权逻辑变更，都绑定版本与评估结果。将本轮失败样本固定下来防止回归，再用独立新样本验证泛化。本轮报告只能支持定位不足，**尚不能证明整个模块已稳定可交付**。
