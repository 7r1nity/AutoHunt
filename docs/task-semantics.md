# 共享任务语义与回归结果

> 本页记录上一版共享正则语义与历史评估。后续重构已将业务解释交给模型、审批改为实际动作绑定；当前职责与验证见 [模型理解与动作审批](model-interpretation-actions.md)。下文旧授权行为和通过率不能当作新版本结果。

2026-10-10 实施。目标是减少同一句请求在解析、规划、授权之间的矛盾，不是删除安全检查或承诺理解任意语言。

## 数据流与责任

```text
完整用户消息 + 有效原任务/补充
  → 共享动作语义（动作、模态、原文位置、撤销分支、未知）
  → 完全消费的简单规则 / 原有小模型路由 / 主模型完整目标规划
  → 规范化计划（目标、分支条件、依赖、来源绑定）
  → 结构/能力/证据校验：修正、澄清、拒绝
  → 持久步骤授权核验 → 有界执行器
```

`core/task_semantics.py` 是动作模态与来源的共同入口。搜索、成长计划、规划和工具权限不再分别实现同义命令、否定、引用、询问判断。能力名称和工具 schema 来自工具注册表；新的业务动作仍需要注册工具、实现执行器并接入共享动作词汇和回归，不是加一个 prompt 就能得到新能力。

共享解释按动作判断，而非给整句一个可执行布尔值：同一句里搜索可以被授权，投递可以被撤销，JD 中的“自动投递”只是数据。引号内条件值不抹掉外部命令；未闭合的指令引用不授予权限。控制命令还核对目标，取消薪资限制不等于取消浏览器任务。

参数规则只处理完整消费的简单表达。未消费内容不成为职位关键词，保留原文进入模型规划。旧的实习/校招能力预拦截已移除。未知表达不默认放行；模型生成的计划没有真实动作来源时，仍不能执行写入或投递。这意味着开放表达仍可能需要澄清，不能宣称规则词表完全消失或任意同义表达都已支持。

## 条件、续接和授权

- 搜索薪资、投递分数、成长计划分数/薪资分别保留在对应步骤，依赖绑定实际搜索结果；不把所有条件压成一组全局搜索参数。
- 条件树沿用跨行业 all/any/not 与原文证据，新增 require/prefer/allow。硬条件缺事实仍为未知；软偏好和允许包含不排除岗位。偏好证据会被记录，尚未实现全站优先排序或完整 UI 排序展示。
- 未执行原任务可被部分撤销和参数补充；“只保留搜索和成长计划”从原目标中减去投递，不是新的授权。失败修复仍引用完整原任务，不能用短回复覆盖它。已执行/结果不确定的步骤不重放。
- 校验只给已核实动作生成 `authority_binding`，包含工具、来源位置和摘要。新计划持久化该绑定及归一化理解。运行时验证绑定和持久步骤、精确参数、简历版本、撤销、归属和有效期，不重复解释同一个已验证命令。
- 原计划没有绑定时保守兼容；旧筛选预览因规范化指纹变化可能需要重新生成，不自动扩大授权。真实站提交保持禁用，模拟站预览、一次性权限、验证码接管、结果不确定不重试仍在。

候选计划引用错了、但完整请求确有该动作：内部修正。原请求没有动作、只有询问/引用/假设，或动作被撤销：阻断，不能让模型修复“制造授权”。真实缺参数才澄清；JSON 修正和语义修正仍各最多一次，整体 60 秒预算不变。本次没有改变模型部署配置或执行超时预算。

### 保留的失败

`conflict-01241`：`帮我找工作 城市深圳 城市杭州`。旧合成 gold 要求确定性拒绝，当前 best-effort 提取留给模型解释为城市列表/条件冲突，不直接拒绝。这个标签与契约存在歧义，保留原失败，未改预期、未增加 xfail。完整基准因此仍返回非零退出码，不能声称全绿；需要人工确定该表达应合并两个城市还是要求澄清。

既有场景的两项 xfail 是空技能评分行为及 decision ledger 缺读取器，非本次共享语义变更，未顺手修正。成长计划内容质量、真实小模型路由、真实 LLM 长指令、模拟站完整投递闭环、真实站登录与 DOM 兼容均未由本次验证覆盖。

## 后续入口回归修复：搜索前误执行投递检查

用户原句“帮我找十五份 月薪15k以上的工作 85分以上的直接投递 可以是实习但是不要外包”在真正的会话派发入口复现：上一轮虽统一了动作权限，但 `shortcut_safe` 仍使用一份遗留目标计数正则，漏认中文数量、搜索动词与工作之间插入的条件。新增“直接投递”支持因此在此路径提前调用投递工具，账号未绑定检查返回后，浏览器从未启动。这不是用户表达错误，也不是删掉了浏览器登录代码。

已将快路径目标计数也接入共享动作语义，并要求独立投递快路径完整消费单条指令。多目标或附加条件必须交给规划，不得从整句只提取一个分数就执行投递。`可以是/可以包含` 与 `可以有` 统一为允许包含的模态。

新增14项回归：8项真实前台派发入口（4种数量/动词表达×有无路由器）和6项投递快路径完整消费。入口使用脚本模型输出正确且带参数证据的计划、合成执行器替代浏览器；生产路由/校验/授权/持久化操作和DAG真实运行。断言无账号绑定时只发起搜索，登录等待不执行依赖；核实搜索完成、账号绑定后才投递，而且重复推进不会重投。未将“启动浏览器”或“登录成功”当成搜索完成。

修复前的原句确实复现“先绑定账号”回复；其他测试脚本字段和待实现函数错误单独修正，不算额外业务缺陷。日志分别保留在 `20261010T064358.845757Z`（初始复现）、`20261010T064444.008552Z`（修复中）、`20261010T064537.242519Z`（939项重点契约通过）。最终完整基准 `20261010T064605.487554Z` 为2,884通过、1条原有城市标签争议失败、114跳过，总规格2,999；`20261010T064607.872040Z` 的14项隔离DOM通过，外部模型调用均为0。既有offline/state仍为134通过、2既有xfail；语法、类型和补丁检查通过。

当前后端原启动方式没有自动重载。只读核实搜索、投递及会话任务为空闲，自动/每日任务关闭后，已仅重启后端，保留前端、模拟站和历史数据，并通过原有只读API核实响应。不为验收执行用户这条真实请求，也没有用配置DeepSeek跑模型理解；完整招聘业务E2E仍未由本轮覆盖。此补充说明上一轮未覆盖的真实入口回归，不能以规划组件通过率代替入口和环境验收。
