# 对话命令、范围补充与模拟站投递

## 同一份语义契约

规则快路与工具授权共享 action_language 的分数范围与正向动作判断。计划生成接受“成长计划 / 学习计划 / 提升计划 / 学习方案”等说法；询问、否定和引用不是执行命令。具体内容仍由 LLM 根据当前简历与真实 JD 生成，并检查逐字引用、可验收任务与事实来源，不靠 prompt 单独保证质量。

计划分数筛选发生在选择 JD 证据时，而不是仅把范围写在 prompt 中。“90 分以下”按严格低于 90（0–89）处理；“90 分以上”按 ≥90 处理。模型不能通过参数扩大用户指定范围。只选择当前简历终态搜索的证据，过滤之后最多取 20 份详细 JD。

范围内没有有效样本时，不编造、也不自动改用别的分段。记录原始生成请求、简历版本、待补范围和 10 分钟有效期；用户接着说“那就90分以下的”会补充范围并执行原请求。换话题、换简历、超过 4 轮或过期后，不能用省略句再次授权。请求在调用生成模型前消费，失败不自动重复。

## 有限模拟站投递队列

`mock_delivery_start` 接受当前轮明确的自动投递命令和最低匹配分；不接受泛化的“好的”，也不支持 BOSS/智联等真实网站。当前简历已搜索的最多 200 个符合分数的职位为一次有限批次，不开启每日任务、不影响未来搜索。

队列持久化在 SQLite，逐职位绑定简历 ID/版本/摘要、职位内容指纹与最低分。每个职位仍经过预览及一次性授权。执行器先沟通、等待页面明确回复及按钮可用，随后发送简历；不会伪造招聘方回复。已有投递记录、失败、结果不确定、简历或职位变化不会被自动重试；没有沟通回复的直接投递页面需要人工核对。

共享浏览器串行执行，不要求每个等待回复的职位占用浏览器。登录/验证码/MFA 保留人工接管。投递任务绑定所属会话，运行记录可查看和中断；“停止自动投递”取消本会话队列，已经发出的消息/简历保留。入队不等于已投递，看板和统计只展示观察到的阶段。

## 回归测试

- `agent/tests/test_action_requests.py`：原始用户句式、无样本后的范围继承、非授权问句、简历范围隔离、模型参数不可覆盖用户分数、真实网站排除、沟通/回复/投递顺序、重复授权及取消。
- `agent/tests/test_delivery_automation.py`：人工接管、提交结果不确定、不重试、站点白名单。
- `agent/tests/test_board_layout_ui.py`：隔离数据与只读 API，四种宽度下卡片边界、按钮与日期，不修改用户记录。

测试不向真实招聘网站发申请；这些用例不能证明真实站点兼容性。
