# 意图理解与任务续接重构（2026-10-09）

## 为什么重构

之前的诊断覆盖了单句路由、独立规划、参数与安全校验，但遗漏了“复合请求规划超时 → 状态持久化 → 继续上文任务”的真实控制链。浏览器处于 idle 时，旧恢复函数直接返回状态，上层却可以回复“已继续”。断言数量不能代替用户故障链的覆盖。

本轮没有替换整个 Agent 框架，也没有把所有指令交给大模型。保留规则 → 小模型 → 主模型分层；在路由之前解析上下文任务指向，将无工具的请求理解与纯契约校验分离，执行仍经原工具注册表和授权策略。

## 当前职责边界

1. **上下文任务定位**：新增 `workflow/requests.py`。保存原请求、运行 ID、简历版本、条件、执行开始事实与失败状态。尚未执行的失败请求可以在明确续接后重新规划；暂停的存活浏览器才恢复。不能将 idle、空任务、其他会话或未知写入解释成成功恢复。
2. **快速规则**：只处理完整匹配的高频动作和参数语法，未消费的文本转入理解层。规则不是行业白名单；岗位名仍需通过安全形状校验。数字覆盖分组金额、中文数词、匹配分区间与条件冲突；显式城市集合不允许只保留其中几个或丢掉白名单外的目的地。
3. **模型理解**：复合目标生成同一份结构化目标/DAG，带当前 DST 和有预算的近期对话。有效单目标追问中的分数范围回答、已知不支持的招聘类型条件使用窄上下文契约快路径；快路径也经过相同验收，不扩张授权。
4. **纯规划验收**：`validate_draft` 不调用模型或执行器。核对用户原话、全部目标、工具能力、参数、分数范围、依赖和授权；格式最多修复一次，所有尝试共用60秒规划预算。模型输出正常不代表工具动作已授权。
5. **执行和运行状态**：仍由现有执行器负责。超时保留原请求，不自动重试；聊天追问完成保留 clarifying，后台终态条件更新不能覆盖新任务。写入/外部动作开始后，通用续接不能重放。
6. **可见进度和停止**：规划展示阶段/等待时间，不输出推理。停止按钮和完整中断命令绕过繁忙聊天队列；创建请求尚未返回 ID 时记下停止意图，之后按 ID 取消。取消清理与 HTTP 生命周期分离，确认最多等待1秒；不确定写入保留待核验、后续步骤授权失效。

## 核心故障链的预期行为

用户提出“15份、15k以上、上海/杭州/深圳/重庆；高匹配投递；低匹配成长计划”。若规划超时且无步骤执行，再说“继续任务”，重新理解并规划**原来的全部目标**，不是执行 `browser.resume(idle)`。新的搜索依然保留数量、薪资和四城，投递与成长计划依赖本次搜索完成。不会因重新规划而绕过本地投递预览、一次性授权、简历绑定或不确定结果保护；真实网站投递仍禁用。

若原文还有“尽量实习或者校招”，当前执行器缺少招聘类型筛选/排序字段，先明确能力缺口，询问是否去掉该条件；未确认前不执行半条请求。此处修复的是条件理解和能力契约，并非已经实现招聘类型筛选。

## 生效

后端需完整重启以载入新状态和规划契约；刷新前端后使用新的停止入口。不要在有进行中搜索/投递时强制杀进程以部署。历史数据没有删除，旧会话字段兼容；明确失败消息允许有限的旧任务定位迁移，但不恢复历史副作用授权。

### 线上本地进程核对与追加修复

用户再次报告 `已继续浏览器任务。idle` 时，只读核对发现8000端口的 uvicorn 进程仍从2026-10-08 23:05运行，早于重构提交（2026-10-09 00:31），未重新加载代码。运行记录确认该回复来自旧进程，活动任务为空，浏览器执行器为 idle。代码推送不等于运行进程更新。

同时补齐另外两处实际问题：

- “我的需求是什么”使用只读快路径返回原请求/任务状态和当前条件，区分简历推导方向与用户已确认需求，未设置的数量/薪资不猜测。上下文读取投影剔除庞大对象快照和重复执行参数，保留请求/缺失信息；规划执行器的条件读取使用自然语言，不再直接显示内部工具JSON。
- 普通暂停恢复在工作协程下一步行动前重新检查页面登录与验证码；模拟站启动和恢复共用核验循环。BOSS不再因用户确认而忽略同一验证提示；登录前置/恢复需正向页面证据，未确认登录或验证未消失继续等待人工接管。空执行器的旧恢复API返回409，不是假成功或500。
