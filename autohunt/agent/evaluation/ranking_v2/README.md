# ranking_v2 — 分级、对抗式排序评测集

v1 的相关性标签是 `(总年限≥要求) ∧ (学历≥要求) ∧ 领域相同` 加技能覆盖，正好是匹配器输入里的字段，任何按同一公式比较的系统都能复现理想排序，于是 NDCG@5 停在 1.0000。v2 保留"合成规格 oracle"的诚实定位，换掉的是**要推理什么**。

## 数据

40 个虚构候选人 × 每人 20 个候选岗位 = 800 对，10 个合成领域，无随机数：`spec.build()` 每次生成同一个数据集，摘要见 `spec.digest()`。

每个岗位池固定混合：

| 类别 | 数量 | 说明 |
| --- | ---: | --- |
| 满配 | 4 | 六项条件全满足 |
| 差一项 | 3 | 资深度或交付范围差一档 |
| 近失 | 1 | 行业年限差 1 年，或两项软信号缺失 |
| 弱相关 | 1 | 技能覆盖 75% |
| 未知 | 1 | JD 不写学历年限，eligibility=unknown，相关度封顶 3 |
| 硬条件不符 | 6 | 年限差 2 年、学历差 2 档、外包且候选只要正式、异地不可远程 |
| 跨领域 | 4 | 方向不符，相关度 0 |

## 口径

- 相关度 0–4：硬门槛先否决，再用四项软信号（行业年限、技能覆盖、资深度、交付范围）加权合成，`spec.label` 是唯一真值来源。
- 主指标是同分均匀随机期望（`metrics.tie_aware`），同时报实际写出顺序（`metrics.realized`）；`tie_aware` 与枚举排列的等价性有契约测试。
- P@5 在 10/20 相关的池子里会饱和，区分力主要看 NDCG@5/@10、高匹配@5（≥3 档）与支配对准确率（档位差 ≥2 的成对比较）。
- 锚点：随机（闭式期望）、关键词、浅层字段读、生产规则回退、标签 oracle。没有随机锚点，0.75 这种数字没有意义。

## 用法

```powershell
# 离线：数据集 + 全部锚点（0 次外部调用）
python -m evaluation.ranking_v2.harness --out <目录>
# 模型：受持久预算约束，单文件上限 300 次
python -m evaluation.ranking_v2.harness --out <目录> --model --budget 290 --model-queries 14
# 回放：从冻结打分重建模型系统，不再请求
python -m evaluation.ranking_v2.harness --out <目录> --predictions <目录>
# 契约
python -m unittest evaluation.ranking_v2.contracts
```

模型路径复用生产匹配器（`app.browser.screening.match_job`）与共享物理请求预算；`match_job` 失败会静默回退规则分，因此 `harness.model_rows` 用 traced 包装单独统计成功/失败调用，并在 3 次连续失败时中止，避免把回退分当成模型分。

## 已知限制

- 标签是合成规格，不是人工 Gold；`rubric_sensitivity` 用"去掉资深度/交付范围"的宽松规格量化标签口径的影响（严格标签下其最优排序 NDCG@5≈0.789）。
- JD 文本把"行业年限"写成硬性要求，而规格把它算作软信号；这会让模型的 `qualification.status` 与规格不一致（详见首轮报告），下一版要统一文本、规格与匹配器契约。
- 固定 20 岗位池测重排序，不测全站召回；投递与恢复指标在另一套 24 场景装置里。

首轮结果与结论见 [ranking-benchmark-v2-2026-10-26.md](../../../docs/ranking-benchmark-v2-2026-10-26.md)。
