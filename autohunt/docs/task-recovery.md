# 任务接续与全流程故障处理（2026-10-10）

2026-10-12 补充：动作范围确认持久为 waiting_approval，继续/重启保留等待，不替用户批准；旧确认拒绝且有“尚未执行”证据时可迁移为这一等待状态。具体策略、子运行确认转移及局部结果刷新见 [执行决策](action-decisions.md)。

本版接续以持久执行记录为依据，不把聊天中的“已继续”当执行证据。规则、小模型、主模型路由保持；复杂条件仍由模型提取。以下是实现边界，不是任意语言/真实招聘站的完整验收承诺。

## 接续入口

- 会话发送“继续任务 / 继续中断的任务 / 重试 / 从断点继续”，先定位原计划，再决定能恢复哪些步骤，不调用模型重拆已执行任务。
- 非快捷表达仍可以经模型调用无参数 `task_continue`；该工具使用同一接续入口，没有单独的模型授权或恢复算法。恢复浏览器意图的直接派发也优先检查任务接续。
- 运行记录的 resume API 创建同会话子运行，保存 `parent_id`、`resume_source_id`；旧终态不改写。下一次续接选同一逻辑计划的最新子运行，不能再次从旧失败父节点重放。
- 无唯一原计划时澄清；无执行计划（例如首次规划超时）仍走既有“定位原请求再规划”的路径，而不是恢复 idle 浏览器。变更条件/撤销分支不是纯续接，走既有任务修订流程。

恢复时读取完整执行事件和同会话运行记录，不使用模型上下文截短窗口；事件分页超过 200 条仍能定位成功回执。模型不决定某步是否执行成功。

## 断点决策

| 原状态/阶段 | 处理 |
|---|---|
| 已完成搜索/报告/动作 | 保留结果、任务 ID、顺序与参数，不执行、不重新输出 |
| 搜索执行器丢失/页面关闭 | 明确续接后恢复同一搜索 ID；重连浏览器、核验登录；跳过有持久回执的职位及已判定跳过的 URL |
| 搜索记录完成但计数未更新 | 用职位回执修复计数，避免丢失目标数量进度 |
| 原搜索包含演练沟通/投递 | 不能作为只读搜索自动重放；核验已发生的副作用 |
| 旧版本工具执行前因过期/旧摘要损坏拒绝 | 保留原参数、原 `user_requested` 与简历绑定；明确续接从安全断点恢复，不再核对通用摘要。投递仍需原已确认范围及独立预览令牌 |
| 已撤回/取消、简历变化、范围不一致 | 不自动恢复旧动作；确认新的范围。参数结构错误仍须修正，实际投递保留独立保护 |
| `claimed` + 精确成功回执 | 按逻辑计划/步骤/工具及启动参数配对成功回执，恢复为完成或等待对应外部对象 |
| 写入/沟通/投递结果不确定，无成功回执 | 不重放；保留待核验。依赖它的步骤跳过，独立安全分支可以继续 |
| 尚未执行的步骤 / 前置失败而跳过 | 前置可恢复才继续；已经完成的前置不重新执行 |
| 活跃执行器 / 登录接管 | 不启动第二个执行器；接续原暂停执行器并核验页面。正在执行的任务返回实际等待/执行状态 |

搜索断点是“已处理职位 + 完整请求”级，不是浏览器 DOM 游标：列表可重新读取，未写回执的匹配推理可能重算。任务启动时保存完整 `BrowserSearchRequest`；恢复不合并后来会话的城市/薪资/数量或默认偏好。旧搜索缺少此记录则要求明确重新搜索，不猜参数。

明确续接最多5次，预算持久化，重启不能归零。通用计划30分钟执行授权门已删除，投递令牌自身的有效期不变。活跃执行器继续仍沿用原尝试，不能通过续接同时开两套执行器。终态、撤回和结果不确定不是自动重试信号。

## 自动重试与停止

既有推理/幂等读取重试和规划修正保持有限预算：安全读取暂时性错误最多尝试 3 次（含首次）；权限、缺参数、未知错误不自动重试。流已输出不重放。规划失败保留原请求，不自动启动半条命令。

投递执行器仅在明确未到沟通/提交点击（或沟通已确认但未提交）且发生暂时性错误时有限重试；重试次数保存在投递运行中。浏览器锁忙则稍后检查，不消费新授权。沟通也是副作用：点击前持久化 `communication_started`，回执丢失、中断或看门狗触发后进入待核验，不重复点击。提交仍有既有账号/职位/简历绑定、预览、一次性授权及成功证据核验。自动恢复队列只选择明确 `failed_transient_before_submit`；参数/绑定错误的 `failed_precondition` 和旧版未分类失败不能再次被另一层自动重试。

停止沿用会话级取消协调器：撤回队列，取消并等待子任务释放浏览器，不清历史。部分结果和已确认投递保留；停止命中未知点击则待核验。此版没有给同步阻塞代码增加 OS 级硬中断，也没有实现通用自动核验所有未知写入的补偿事务。

## 等待 HR 回复

等待未发送简历的 HR 回复没有生命周期超时。默认 30 秒周期，每个运行受最近检查时间限制；一轮最多检查 50 个有效运行，按最久未检查优先，不因前 50 个长期等待而饿死后续任务。等待释放浏览器，不占新任务准入预算。

重启后从持久运行和队列恢复监测，沿用原预览/简历绑定，不重建授权、不重复发消息。招聘方回复、按钮解锁且绑定仍有效才提交。浏览器忙时延期；验证交给用户；简历/职位变化、撤回、不可核实点击则停止自动动作。已投递岗位不进入“再次发送简历”的回复队列。

“持续”是 Agent 服务在线、浏览器可连接时的周期观察，不是 websocket 实时推送，也不会绕过登录/MFA；关闭 Agent 期间不监测，重新启动后恢复仍合法的等待。此版不开放 BOSS/智联真实提交。

## 输出和日志

原搜索报告通过 `report_reference` 引用，续接不重新发布正文；已在前台响应输出的完成步骤按逻辑计划/步骤 ID 排除后台重复汇总。工具结果和统计不删除。新增事件：`recovery_resolution`、`recovery_decision`、`plan_response_selection`；工具开始/结束附 `plan_id`、`step_id`。2026-10-11 已删除通用工具层的过期/摘要绑定拒绝；执行器仍记录取消、简历变化和任务归属，实际投递模块记录自己的预条件和令牌结果。

历史记录保留；新增搜索检查点纳入既有清理按钮的明确清理范围，本次没有执行历史清理。修改后需要重启后端；本次不主动恢复用户真实历史任务或提交申请。

## 评测与诊断

`agent/evaluation/corpora/recovery.json` 包含 669 个合成规格：432 个状态/副作用/失败/撤回组合，216 个简历变化/取消/脱敏损坏边界，21 个接续与非命令表达。组合样本不是 669 个人工审核的自然语言样本。

`python -m evaluation.recovery_contract` 加上 23 个集成契约，共 692 项检查；使用生产运行器、工具注册表、加密 SQLite、搜索检查点和投递状态机，执行器/页面是合成替身。验证目标包括原参数保留、最新尝试选择、回执恢复、独立分支、前后台去重、HR 等待/重启/公平性、按钮响应丢失、账号变化、关页、取消、重试耗尽和 API 归属。

另复跑动作 15 项、隐私 14 项、报告 14 项；隔离 Chromium DOM 夹具 14 项通过。共 749 项检查。模型调用、真实招聘搜索/投递均为 0。

开发轮次没有覆盖日志：首轮 683 项中 1 个失败是测试错误地要求默认 HIGH 风险策略拦截 MEDIUM 的本地成长计划；按实际安全要求改测 HIGH 的投递，不降低生产授权。扩充入口测试后 692 项中 1 个错误是测试误写 `MainAgent` 导入，改为实际 `AutoHuntAgent`。两轮失败文件保留。检查同时补齐了恢复混入后来条件、回执与计数写入间崩溃、前台/后台重复渲染和长期回复队列公平性的问题，并为这些行为加入断言。

逐轮本地日志在 `agent/test-results/recovery-contract/<UTC时间>/`：`summary.json`（语料/源文件 SHA256）、`traces.jsonl`（期望/实际/调用及事件）、`failures.json`。失败返回非零；源文件变化需重新运行，不覆盖旧报告。失败轮次：`20261010T153707.357853Z`、`20261010T154722.266451Z`。最终轮次见 `docs/evaluation.md`。

局限：不能穷尽“所有可能情况”。这是离线契约和 DOM 适配器评测，不是实际 DeepSeek 理解率、完整模拟站后端 E2E、真实站成功率或跨进程 exactly-once 证明。计划级接续保护已实现；效果不确定且无法找到精确成功回执的写入仍需人工核验。历史大基准的旧授权断言/替身失败依然单独保留，没有算入本次通过数量。
