# 命令误拦截：代码核对与修复（2026-10-12）

先核对修复前版本、当前代码及本地保留的运行/备份记录，再决定改动。历史缺陷与当前缺陷分开，原始请求、数据库和日志不上传仓库。

## 核对结果

| 提出的原因 | 修复前代码中的实际情况 | 本轮处理 |
| --- | --- | --- |
| 重复判断用户措辞是否授权 | 通用 `AgentToolPolicy` 已删除；模拟投递仍要求模型解释出的 `user_requested` | 保留明确范围；缺确认时针对范围提问，不要求固定口令 |
| 原句引用不一致硬拒绝 | `invalid_citation` 已是警告 | 不重新加回原句匹配门 |
| 目标—步骤漏绑拒绝 | `goal_binding` / `uncovered_step` 仍可否决结构正确的步骤 | 降为可观测警告；工具、参数、依赖环等真实结构问题仍有限修复 |
| 当前计划指针变化导致旧任务失效 | 执行器将会话 `tasks.plan_id` 与执行计划 ID 不同视为授权失效 | 移除该推断；检查实际取消记录、任务会话和绑定简历 |
| 修订不能追加动作 | `revise` 携带 `steps` 被拒，修订只接受参数更新 | 共用步骤契约，支持增量添加、更新和撤销未执行步骤 |
| 所有状态更新没有事务 | 已有 SQLite 锁、事务和原子激活；不是普遍缺事务 | 复用已有锁/事务、版本检查及防陈旧保存机制，不重造状态库 |
| 摘要误脱敏、旧类型预检查 | 旧备份确有被改坏的摘要；内部完整数据和通用授权路径此前已修复 | 不新增摘要门；风险分级目前是审计，不是运行时拒绝开关 |

直接重现的最新缺陷是：正在搜索时追加一个有独立语义范围的投递动作，模型返回 `operation=revise` 和新增 `steps`，两轮都被 `invalid_revision` 拒绝。不是城市识别失败，也不是投递按钮失败。

## 修改后的职责

- 模型解释岗位词、参数、布尔条件和动作范围；规则继续负责高频完整命令分类及停止。工具 schema 不变成第二套自然语言解释器。
- 校验真正不可执行的工具名、参数类型/范围、未知业务字段、重复 ID、依赖错误和环；目标注释漏绑及引用改写记录警告，不能单独取消执行。
- 投递范围来自有效用户请求；不明确时询问。真实网站投递仍关闭。账号、简历/职位绑定、一次性预览授权、验证码接管、结果不确定不重放仍保留。
- 导航用的当前计划指针不是撤销凭据。实际运行记录的取消状态、任务会话和步骤撤回才决定停止。
- 已完成动作不能修改或重放。追加时原搜索尚在执行就修订同一任务；搜索在规划期间结束，则建立同会话子运行，保留已完成结果，仅运行新增步骤。
- 后续消费者绑定唯一搜索/重新筛选的任务证据；有多个来源且无法明确选择时追问，而非拿最新看板凑数。

## 独立投递条件

`mock_delivery_start` 现在支持可选 `min_score` 与 `filters`，不是只能按匹配分选择。省略分数不人为加阈值。条件树复用跨行业 `condition/all/any/not`，不靠“正式/实习/第三方”专用枚举扩展能力。

只从本次任务/当前简历的最多 200 个已有有效候选中选取。相同语义叶、相同完整 JD 事实摘要且连续原文引用仍可核对时复用已有判断；没有事实摘要的旧证据、改变过的事实、新条件和 unknown 重新核对。数值薪资继续确定性判断。投递范围为 fail 或 unknown 的职位不入队，分别报告数量；不会改写原搜索范围。

队列保存本分支的条件和证据，逐职位发送仍核对原有简历、职位指纹和一次性凭据。筛选期间的停止或简历变化阻止迟到入队；取消结束后也不能被之前的筛选回调恢复。

## 验证与限制

在 `autohunt/agent` 运行：

```powershell
.\.venv\Scripts\python.exe -m evaluation.command_recovery_contract
.\.venv\Scripts\python.exe -m evaluation.command_recovery_contract --regression
.\.venv\Scripts\python.exe -m evaluation.presentation_contract
.\.venv\Scripts\python.exe -m evaluation.recovery_contract
```

新增命令接续契约包含历史失败的输出形状，而非只构造完美计划：规范化、加密 SQLite 持久化、数据库重开、后台 watcher、终态竞态、当前指针切换、真正取消、会话隔离、简历变化、证据复用及未知排除、重复队列保护。结果和失败轨迹保存在忽略提交的 `agent/test-results/command-recovery/`。脚本模型和执行器替身不调用外部服务。

这些是组件与持久化集成测试，不是模型理解准确率或真实浏览器端到端通过率。尤其没有验证任意改写都能被模型正确解释。首次错误测试轮次保留；旧断言“修订不得追加步骤”按新契约调整，未知工具、依赖环和未确认投递的反例仍保留。

本轮新增18项，去重组件回归164项和既有恢复矩阵692项均通过。后两者是测试执行数，不是856个独立自然语言请求；不少矩阵用例来自组合枚举。无外部模型调用、用户招聘操作或实际历史清理。

尚未解决：按类别各找 5 份的**分组配额**没有专门分配器，条件 OR 不等于配额；成长计划分支仍支持已公开的分数/月薪字段，不支持任意语义过滤树；语义筛选 unknown 不能猜成满足。该修复不承诺任意任务、任意网站或模型返回都能直接执行。
