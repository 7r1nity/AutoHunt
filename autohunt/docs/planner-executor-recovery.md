# 规划与执行：动态修订和接续

本轮以 `b3c84ac` 测试基线为起点，修复规划/执行接口和状态流转，不新增自然语言授权正则，也不取消真实站禁投、逐职位预览、一次性票据或简历/账号绑定。

## 统一语义

- 模型负责目标、参数、条件与依赖；应用负责哪些动作实际发生过、哪些结果可复用。完成回执不能由新的模型草稿改成 pending。
- 计划最多32个节点，执行器每批最多领取8个节点，批次之间交还调度机会。不是无限层级规划或任意长度任务的承诺。
- `RevisionDraft` 提供新增、取消、更新参数、更新待执行依赖、刷新分析、暂停及问题列表修订。已领取、完成和未知结果节点不能原地改写。
- `StepUpdate.depends_on` 可以插入新前置步骤；所有更新在深拷贝图中验证后通过 CAS 提交，循环、无效依赖不会污染旧图。
- 新节点ID撞名且没有歧义引用时生成新ID，旧节点不变；有依赖引用歧义则返回规划修正，不猜引用指向。
- 纯控制依赖变化不会撤回同一范围确认；参数、证据或撤回变化才影响对应确认。

## 运行中的搜索修改

不能直接改浏览器正在使用的请求对象。对正在执行的、无投递副作用的搜索：

1. 把新条件保存为 `staged_arguments`，原 `arguments`、任务ID与已有结果保留；计划暂停，阻止后续消费者使用旧范围。
2. 模型可见暂存参数，后续修改以它为最新条件，不能回退到旧请求。
3. 用户继续时核对简历范围及浏览器归属，停止并JOIN旧只读worker。
4. 原请求/任务ID保存到 `attempt_history`，再激活新参数；正常搜索工具创建新搜索ID并重新核验页面与登录。
5. 旧搜索记录不篡改，已发送内容不重放；新消费者以新任务证据继续。

这不是运行中浏览器请求的热替换，也不是保留旧游标后假装应用了新条件。含自动沟通副作用的 dry-run 搜索不走这条自动替换路径。

## 等待不是失败，也不是完成

`workflow/lifecycle.py` 统一解释成功回执和等待状态，前台执行与恢复使用相同转换。

- `waiting_input`：缺业务输入。步骤级问题/槽位暂停该节点；独立且参数完整的分支继续。没有归属的旧全局问题不会放行猜测的写动作，但不阻止无关读取。
- 输入等待持久化为运行的 `waiting_user`，不保留轮询worker/模型槽。补齐参数或修订后重新调度原owner；没有回答问题时“继续”不会反复调用工具。
- `waiting_binding`：账号绑定仍在进行，不能把 `queued=0,binding=searching` 当入队完成。绑定成功后按同一范围继续入队；失败转为补参等待。
- 共享浏览器属于另一会话时等待资源，不绑定、监测或取消其任务。资源释放后才启动本会话绑定。
- 撤销分支的依赖后续继承 `user_withdrawn`，不再把正常撤销算运行失败。用户可以明确重连仍需执行的节点。
- 模拟投递的队列入队回执不表示简历已发送；实际发送由原有逐职位监测/预览/授权执行器确认。不能用本轮计划回执宣称整个外部投递闭环已完成。

## 接续与副作用阶段

每次领取有独立 `execution_id`。可信应用适配器通过 `effect_checkpoint()` 报告阶段，事件和检查点记录与同一领取绑定：

| 阶段 | 意义 | 接续原则 |
| --- | --- | --- |
| unknown | 没有可信阶段记录 | 写/外部动作不盲目重放 |
| preparing | 适配器证明仍在准备，未产生所跟踪效果 | 明确接续时可以重新准备 |
| started | 写入/外部效果已开始 | 先核实结果，不重复发送 |
| committed | 所跟踪写入已返回 | 仍需精确成功回执确认具体结果 |

阶段单调推进，started不能退回preparing。旧记录和未接入阶段记录的执行器仍默认unknown，不能根据异常文字“发送前”判断安全。

模拟队列写入及成长计划保存接入可信阶段记录；其他写工具仍采用原保守策略。只读重试预算、单次票据及逐职位实际发送保护保持不变。

成功回执匹配计划、节点、工具、参数及执行ID。旧尝试晚到的成功事件不能完成新尝试；新草稿保留完成节点/结果，不再规划成待执行写动作。

## 验证与日志

原21项状态失败已修复。运行状态矩阵、实际运行管理接口的合成集成测试，以及原有命令、恢复、审批回归。没有真实LLM调用和完整招聘网站端到端投递，因此不能宣称语义理解准确率或生产任务成功率。

## 保留的边界

需要真实模型留出集验证指代、复杂条件与完整目标理解；需要完整模拟站端到端验证登录/表单/实际发送与服务恢复。长期记忆召回、多进程fencing、所有运行中副作用的热修订、逐批外部投递与计划根目标的统一收尾仍不是本轮完成项。

已执行或结果未知的步骤仍不能原地取消/修改来掩盖历史。已入队的投递由现有停止队列入口取消，不把删除一个完成的计划节点当成撤回实际发送。
