# 100+ 投递容量验收：执行容量与产品入口分开判断

测试日期：2026-11-29（北京时间）。被测应用基线为 `29e3dfa`；本次只增加评估代码、结果和说明，未调整搜索上限、投递、授权或监测逻辑。

当前结论：**执行链已验证能处理120个预先保存的岗位；正常产品链路仍有100个搜索目标和100张看板卡片的限制，不能据此宣称单次“搜索并投递120个”已经完整支持。**

## 分层结果

| 环节 | 结果与口径 |
| --- | --- |

| 120个岗位的沟通 | 120/120完成；全部在任何HR回复之前完成，等待回复释放浏览器 |
| HR回复识别 | 生产`sync_once`通过只读HTTP轮询检测120条合成回复；不是直接写入“已回复”标记 |
| 回复后发送简历 | 120/120经隔离API回执及本地SQLite最终状态核实；重复沟通0、重复提交0 |

## 后台等待与交互延迟

运行器另做约6.962秒的短时观察，启动120个真实`watch_delivery`协程，保留生产1秒观察间隔，使用实际SQLite与加密RunStore。每个协程完成4–5次观察，合计574次；120条投递状态事件持久化，133条运行参数记录均加密。没有模型、浏览器或发送操作。

| 测量阶段 | 结果 |
| --- | --- |
| 新的前台请求入队（10次） | p50 21.214ms，p95/最大26.339ms；仅测准入，不含LLM或HTTP |
| 只读进度汇总（3次） | p50 547.748ms，p95/最大563.903ms；每次都返回120个等待记录并保存聊天结果 |
| 集中启动阶段 | 3.117秒窗口，20ms计时探针出现约3090ms的最大延迟；该段只有1个恢复后的样本 |
| 稳态等待阶段 | 1.126秒窗口、34个计时样本，最大延迟约27ms |
| 进度查询阶段 | 2.044秒窗口、5个计时样本，最大延迟约589ms |

这里暴露了集中初始化和汇总查询时的事件循环阻塞。源码中这些路径有同步SQLite读写；各项开销占比尚未做CPU采样，不能凭这次短测归因到某一条SQL，也不能把少量样本的p95当作生产SLO。后续应评估批量状态观察、错峰初始化和将耗时数据库读取移出事件循环，再做重复与长时间测试。

进度方法由测试直接在事件循环内调用，与运行器内部调用位置相同；独立的同步FastAPI查询接口可以在线程池运行。因此547–564ms是方法耗时，589ms是该调用位置的计时延迟，不是测出的HTTP响应或SSE延迟。

## 明确的限制

1. 搜索候选预算`max_jobs`可以到200，不等于目标数量`result_limit`也能到200；当前后者仍为100。每日任务的200候选配置不能证明普通对话的120目标完整可用。
2. `list_jobs()`默认100条，公开岗位接口没有分页，也不返回被截断的总数。因此“看板只有100条”不能直接解释成“只执行了100次投递”。
3. 投递批次、当前轮证据和稳定列表快照最多200。200只验证了队列边界，本轮完整浏览器流程只运行120个，不外推到更大数量。
4. 普通HR等待查询不截断为50条；每轮最多占用一个浏览器动作，其余岗位可以同时等待。累计超过200的历史观察、长会话消息、网络故障、验证码、网站限流和长时间运行没有在本轮完整压测。

改进应优先统一搜索目标、配额和队列的容量契约，为看板增加有总数的分页/游标；随后从正常搜索入口再跑120个的全链验证。不能只把页面数字改大，或用预先种入120条数据掩盖入口限制。

## 夹具与可复现边界

- 队列与运行器使用临时/隔离SQLite、加密RunStore及虚构候选人；外部模型调用为0。
- 浏览器使用生产投递执行器、适配器和本地模拟招聘HTML。所有站点API由隔离的**内存后端**拦截，外部成功记录与本地SQLite逐岗对应；不是现有模拟站数据库或真实招聘网站的负载测试。
- 合成简历导出、全新无登录资料的浏览器连接和固定简历标识是显式夹具接口，没有修改生产等待时间。
- 看板容量通过独立子进程装配实际ASGI路由和鉴权，替换为隔离岗位库；不启动lifespan工作线程。该接口结果再交给拦截API的生产前端显示。
- 结果保存源码哈希及逐阶段日志。各层分别验证，不合并宣称为一条未经测试的自然语言端到端链路；真实模型的复杂指令理解没有在本轮测量。
- 120个浏览器任务采用同一正常流程、不同岗位ID，不等于120种页面或业务场景。运行器短测、浏览器批量执行与HTTP看板测试是三个独立实验。

```powershell
.venv/Scripts/python.exe -m evaluation.delivery_scale_contract
.venv/Scripts/python.exe -m evaluation.delivery_scale_surface --jobs 120
.venv/Scripts/python.exe -m evaluation.delivery_scale_runtime --count 120
.venv/Scripts/python.exe -m evaluation.delivery_scale_browser --count 120
```

界面容量验收只需本地AutoHunt前端提供静态资源；所有业务API被拦截。浏览器投递基准所用页面资产及源码哈希记录在结果中，替换页面夹具后应重新运行，不沿用旧页面的性能数字。

浏览器runner优先读取本机`mock-site/frontend`，不存在时回退仓库内置`evaluation/fixtures/job_site/frontend`，也可显式指定`--site-root`。本报告的120个批量数据使用本机页面；仓库内置页面另外完成2岗沟通、回复识别、提交和去重烟测。内置页面没有在本轮重跑120个，不能沿用本机页面的性能数值。
