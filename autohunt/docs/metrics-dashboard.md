# 验收与指标面板

入口：左侧「验收与指标」。对话页的「本轮指标」自动打开最新一轮；「任务与上下文 → 运行记录 → 查看本轮指标」定位指定运行。

## 本轮执行

- 支持选择会话和最近 500 轮运行。查看历史会话不会切换当前对话上下文。
- 默认跟随最新一轮，每 5 秒读取运行与账本；当前会话任务结束的状态更新也会立即触发刷新。切换轮次时取消旧请求，避免混用两轮数据。
- 展示最终状态、模型调用次数、工具调用次数、输入/输出 token、记录时长、模型累计耗时、计划版本与步骤状态。
- 模型逻辑调用与传输重试分别计数。token 仅汇总供应商返回的 usage，缺失值显示「未记录」；部分缺失与响应丢失的重试明确标记不完整。
- 记录时长是创建到最后一次更新，可能包含人工/HR 等待；模型耗时是各调用累加，不能当作墙钟时间。耗时缺失也单独提示。
- 失败原因包括运行结束原因，以及模型错误类型、步骤失败、规划失败、超时和结果待核验事件。过程异常可能已恢复，不据此改写最终运行状态。
- 账本只覆盖所选 run，独立搜索/投递子任务需另选查看。工具成功或投递入队不等于简历已送达。
- 每日任务与「总结搜索结果」这条对话分别记账。对话有明确的搜索来源时，可一键跳转对应每日任务；旧记录缺少来源时只提供「最近每日任务」入口，不声称两者已关联。
- 已结束轮次有本地规则执行记录，且没有模型调用或传输重试时，显示「未调用模型」、`0 / 0 token` 和 `0 ms`。旧轮次只有空账本时显示「无调用记录」，不将其未知用量伪装成零；实际模型调用缺失 usage 时仍显示「未记录」。

数据继续来自 `RunStore` 的持久记录和 `execution_ledger` 只读投影，无数据库迁移，无新的执行状态源。HTTP 返回沿用身份验证与脱敏，不包含模型请求/回复正文、简历或工具参数。

## 历史评测

- 提供六份已发布评测/准备报告，按类别选择，显示日期、适用范围、关键指标、原文和结构化数据，可下载 JSON。
- 自动发现 `agent/evaluation/results/context-ledger-regression/` 与 `stateful/` 下按时间命名的验收结果，每种最多最近 100 轮；只读取 `summary.json` 的允许字段，不读取原始轨迹、数据库、模型文本或凭据。
- 工程验收明确区分通过、未通过、数据不完整。源文件在评测期间变化也不标为通过。历史模型评测默认展示为历史记录，不根据个别分数推断整套系统通过。
- 尚未完成的独立标注评测显示「尚未完成评测」，没有参考标签的 NDCG 等指标显示「暂无数据」。
- 面板不会自动运行评测或发起外部模型请求。已有报告的日期与边界保持原样，不能当作本轮模型质量成绩。

后端只读接口：

```text
GET /api/v1/runs/{run_id}/ledger
GET /api/v1/evaluation-reports
GET /api/v1/evaluation-reports/{report_id}
```

前端通过现有认证代理访问对应 `/api/agent/` 路径。报告 ID 由受限目录生成，不接受任意文件路径。文件丢失或损坏会显式返回错误，不伪造空报告。

## 验证

在 `agent/` 运行 `python -m unittest evaluation.metrics_dashboard_contract evaluation.context_ledger_contract`；新增契约也已接入 `evaluation.context_ledger_regression`。

浏览器验证使用隔离数据库、模拟事件和本地前后端，检查失败/未知用量、历史轮次切换、空会话、任务完成自动更新、历史报告与下载、未完成评测、手机宽度及接口错误。未调用外部模型或进行招聘投递。

2026-11-15 补充 `evaluation.daily_metrics_browser`，在已启动的前端注入合成账本并禁止所有 API 写入，6 项检查通过；本地规则、历史未知、缺失 usage 及每日任务跳转保持不同口径。跨模块离线回归 795 项通过，结果可在历史评测中查看；这不是 795 个真实浏览器或模型质量样本。
