# 上下文与执行账本：第一轮架构试验

改造前回退点：`a82df74ff5496fe36527b1f90ebfed075dea2289`。试验分支：`codex/context-ledger-refactor`。

这轮借鉴 EvoAgent 的“统一上下文构建”和“执行观测”思路，不迁移其 Redis、多个 Worker、执行器或权限模型。AutoHunt 现有动态 DAG、追加/取消/修订、断点恢复、HR 后台监测和真实发送保护继续作为执行事实源。此改造不承诺解决所有模型语义误解。

## 1. 模型输入与持久记忆分开

`runtime/context_builder.py` 是纯投影模块，路由、任务规划、原生工具循环共享预算定义，`LLMManager` 在模型传输边界再核对完整请求。原始记录不因输入窗口缩减被覆盖。

进入模型的优先级：

1. 系统/工具协议、当前用户请求、完整当前工具事务。
2. 原任务、最新槽位与分支条件、追问、任务/结果来源引用、简历版本。
3. 最近完整对话轮次。历史助手的超长报告可替换为明确的原文检索提示，用户原句不切片。
4. 已有远期 trace 摘要与公开记忆。它们明确属于历史数据，不构成新指令或授权。

默认最多 8 轮近期历史、6,000 个估算 token。模型输入上限取 `min(48,000, 窗口65,536 - 本次输出上限 - 余量1,024)`；会话投影16,000，分类投影6,000。预算来自 `.env.example` 的 `AUTOHUNT_CONTEXT_*`。默认值是应用配置，不是自动识别的供应商窗口；应按实际模型调整。

估算器使用 ASCII/3 + 非ASCII×2，中文按保守值估算，日志始终标记 estimated。它不是精确 tokenizer；隐藏的供应商协议开销仍可能不同。DeepSeek 的普通、原生工具与流式请求都显式传输出上限。

岗位大量搜索仍将全文 JD 保存在原有职位库，模型会话只带列表来源、数量和少量预览。读取具体序号时使用现有稳定快照/工具，不在每次对话中塞入150份 JD。没有新增向量库，也没有把历史文本变成授权凭据。

原始任务过大时：分类器降级给主模型，不截断条件；必要状态或当前工具事务仍超过主模型输入预算时，停止这次推理、保留记录并报告需要分批读取。不会通过删掉筛选分支来“强行通过”，也不会自动重放副作用。历史原文可通过现有 `context_history_read` 召回；这轮没有新增自动向量召回或模型生成远期摘要。

## 2. 执行账本是读视图，不是新状态机

`runtime/ledger.py` 从已有运行事件、检查点与回执计算账本，不反向改写执行状态。无需数据库迁移。

可关联的字段：run/session → plan/revision → step/execution_id（执行尝试）→ model call_id。步骤执行前设置不可变的诊断作用域，后台评分 Worker 继承的是该作用域，而不是稍后变化的当前计划指针。

子任务可写限定的模型/预算诊断，仍不能借此写 checkpoint、获得动作授权、修改会话或向用户发布回复。后台结果汇总也有运行身份，但不获得工具执行权限。小模型分类、主模型推理、原生工具和流式结果均记录调用信息；没有 `RunContext` 的独立文档调用不归属于运行账本。

账本提供：

- 模型状态、延迟、供应商 usage；没有 usage 的 token 是 `null`，不会被计成0。
- 已知 token 子合计与完整性标志。主模型传输重试单独计数；最终 usage 不假装包含响应丢失的前次费用。
- 已知费用与币种。供应商未给费用、也没注入价格表时 total_cost 为 `null`。离线调用者可向 `RunStore.execution_ledger(..., model_rates=...)` 注入 `provider/model` 价格表，含 `input_per_million`、`output_per_million`、`currency`；有缓存命中时还需明确 `cached_input_per_million`，估算明确标记不是账单。HTTP接口默认不猜价格。
- 工具调用、重试、审批决定与步骤最终状态；工具成功/投递入队不等于简历已送达。
- 当前已观察到的浏览器/投递任务与 submitted 状态。它只覆盖相关 run 的事件，不自动合并所有独立投递子任务。
- 上下文预算与省略数量。并发调用耗时的合计不等于任务墙钟耗时，HR等待也不算模型执行时间。

只读接口：`GET /api/v1/runs/{run_id}/ledger?include_parents=true`，使用现有 API 身份验证。默认只看该 run；开启 parents 后可查看同会话接续链，最多32层，循环或超限有明确标记。公开返回不包含原始 prompt、简历、工具参数、输出正文或隐藏推理。详细内部模型记录沿用原有加密存储与边界脱敏。

## 3. 没有修改的执行契约

- 搜索、结果、投递和成长计划依然按现有 DAG 依赖执行，接续依然以实际回执/失败阶段为依据。
- 简历绑定、账号核验、一次性预览/授权、防止重复发送和不确定结果禁止重放均保留。
- 真实网站发送仍禁用；没有更改模拟招聘站的招聘方回复/发送简历规则。
- 没有自动恢复、重新搜索或投递，也没有清理用户历史；运行中的服务必须显式重启后才加载新版。

## 4. 验证与回退

从 `autohunt/agent` 运行：

```powershell
.\.venv\Scripts\python.exe -m evaluation.context_ledger_contract
.\.venv\Scripts\python.exe -m evaluation.context_ledger_regression
.\.venv\Scripts\python.exe -m evaluation.stateful_scenarios
```

测试使用合成条件、隔离数据库和假模型/执行器，不消费外部模型预算，不操作现有招聘任务。runner 保存日志、合成事件、案例和结果到忽略的 `evaluation/results/`；测试代码持久化到仓库。参数组合和继承 fixture 不应被宣传为等量独立自然语言样本。

回退使用已有 checkpoint 分支/commit，不使用 `reset --hard` 或重写远程历史。由于没有 schema 迁移，旧代码可继续读取原有数据，新增诊断事件可忽略。回退代码前需协调运行中的任务和服务重启；这轮不自动取消任务。
