# 松绑改动的无损修复

本次不回退松绑方向，也不增加同义指令正则。修复对象是 Claude 修改引入的运行缺陷和模块间契约不一致，而非特定职业、薪资或措辞。

## 保留的行为

- 引用和目标注释的形式差异只告警，不作为执行授权。
- 缺参成为步骤级等待，相关依赖等待，独立可执行分支继续。
- 本地可逆动作默认按 HIGH 阈值放行；用户主动配置严格策略时才追加确认。
- 修订仍支持新增步骤、取消待执行步骤、修改参数、派生新分析；已完成回执不重放。
- 规划最多三次语义修复，沿用整体超时和取消机制；不会无限修复。

## 修复的契约

条件表达式：只规范化布尔等价的结合律和无引用单子节点；顺序、重复叶节点、NOT、混合 AND/OR、叶节点模式与分组证据索引保留。六层模型输入加两层运行组合预留，最多256个节点。无法无损解释的条件保存在 `unresolved_arguments`，先使用已有有限模型修复预算，仍失败则暂停对应步骤询问，而非整单拒绝或删条件后搜索/投递。数量分组必须是事实类别，允许/偏好不能自动升级。

依赖与结果：`workflow/graph.py` 是规划和修订共用的接口。消费者依赖生产者（搜索→总结/成长计划），唯一的直接反向依赖可修复；间接矛盾交由有限重规划。多个独立结果来源暂停消费者询问，不任选第一轮。同参数不同搜索仍有独立结果身份。去重仅合并前置条件相同的待执行非结果生产动作，随后重新检查 DAG。已执行依赖记录不可改写。

修订与授权：不存在的步骤不会被访问或被声称已操作；兼容同一步骤补丁合并，冲突补丁追问而非选首尾。简历变化提示核对，不自动复用旧简历授权。原私有预览、一次性授权、验证接管及未知发送结果不重放的保护保留。

确认与停止：确认卡从实际结构化参数展示完整条件和指定对象，不另建 DeepSeek 客户端或后台模型任务。等待五分钟只记录一次提醒；确认时仍核对实际范围与简历。停止在共享工具入口生效，控制工具自身可执行。只读超时保留失败类型、可重试标志和执行阶段。

## 验证及限制

| 验证 | 本轮结果 | 范围 |
| --- | --- | --- |
| 新增反例 | 190通过 | 162个三值布尔表组合、28个条件/图/修订/确认反例 |
| 新增反例加相关回归 | 286通过 | 上述190项加已有96项；可能复用 fixture，不是286条独立自然语言样本 |
| Stateful multi-turn | 229通过 | 生产规划、修订、执行、SQLite、恢复配合合成执行器 |
| 恢复矩阵 | 692通过 | 参数化状态组合与实际恢复逻辑，不是692条独立用户请求 |
| 隔离 Chromium | 通过 | 拦截全部HTTP的合成页面；三个沟通先完成，三个回复后发送，无重复 |

测试曾暴露“两个同参数搜索被合并后绑错结果”和“详细确认范围被通用提示覆盖”，均修复后重跑。旧多来源场景只接受抛异常，现改为检查真正结果：消费者等待输入、无绑定、无工具动作；不是放宽到任选来源。

运行目录为 `autohunt/agent/`：

```powershell
.venv/Scripts/python.exe -m evaluation.loosening_contract --regression
.venv/Scripts/python.exe -m evaluation.stateful_scenarios
.venv/Scripts/python.exe -m evaluation.recovery_contract
.venv/Scripts/python.exe -m evaluation.gated_delivery_browser_contract
```

本轮日志位于 `evaluation/results/loosening/`、`evaluation/results/stateful/`、`evaluation/results/gated-delivery-browser/`、`test-results/recovery-contract/`，包含失败记录、合成执行轨迹和最终状态；不提交运行数据。Windows沙箱禁止 asyncio 的本机 socketpair 时，需要在允许本机测试进程的环境运行。

没有调用真实 LLM，没有发送用户简历/聊天，没有在真实或正在运行的模拟招聘站上发起搜索/沟通/投递。上述结果证明工程契约回归通过，不证明所有自然语言都能正确理解，也不是生产网站端到端成功率。
