# 筛选证据复用与批量补投范围

日期：2026-10-20。适用于本次源码修复；不会自动重跑历史搜索或投递。

## 问题与修复

旧链路先用抓取的标签筛选岗位，再将匹配分析的 matched_skills / missing_skills 合并、排序并截断为看板 tags。投递时将这些派生标签当作原始事实，导致 facts_digest 不一致，原筛选结论不能复用。同一 JD 因此可能再次调用模型，出现搜索 pass、投递 unknown。

- `jobs.source_tags` 保存抓取的标签；`jobs.tags` 继续用于展示和匹配分析。
- `filter_facts()` 是共享的筛选事实投影。标题、公司、地点、薪资和 JD 使用当前值，标签使用原始 source_tags，不使用补充技能冒充 JD 证据。
- 只有事实摘要一致、筛选策略版本一致、语义子条件相同且引用仍能在原文核对时，才复用 pass/fail。不同条件、JD 改写、真实标签变化或策略升级需要重核；不会仅凭一段引用仍存在就信任旧结论。
- 薪资数值判断始终由程序重算，不把模型文字当作金额计算结果。

### 局部同步不能擦除原始证据

手动导入与手动沟通共用的 upsert 采用字段存在性语义：未传 `source_tags`、`filter_evidence` 或 `filter_status` 时保留已有值；显式传入才更新。`source_tags=null` 清空，`[]` 表示已知空标签，不与未提供混同。插入新岗位的行为不变。

这只避免不完整同步误删证据，不保证旧证据永久有效；JD、原始标签或筛选策略实际变化仍会由事实指纹及策略检查触发重核。

## 校招不是岗位性质

模型在同一次筛选中分别记录两轴及各自的原文依据：

| 轴 | 值 | 含义 |
|---|---|---|
| `employment.hiring_channel` | campus / experienced / unknown | 招聘对象或渠道 |
| `employment.kind` | regular / internship / unknown | 当前岗位性质 |

校招、应届及社招本身不能证明岗位是正式全职；月薪也不是正式性质的充分证据。当前为应届实习、毕业实习或实习后有转正机会的，仍应按实习核对。接受候选人过去的实习经历不等于当前岗位为实习。

薪资叶的 `applies_to=internship` 结合同一次调用中有引用依据的岗位性质判断作用域。结构化类型明确为全职时不受实习日薪门槛限制；明确为实习时核对日薪，不将月薪折算成日薪；只有校招或社招标签不能跳过实习日薪检查。两轴冲突或证据不足仍为 unknown，不按月薪、分数或关键词自动猜测。

这是模型解释 + 引用检查，不是独立的事实真实性认证，也不保证模型不会错误理解原文。模型缺失或畸形的可选分类项只降为 unknown，不应破坏其他有证据的条件结果。筛选未知不会自动入队；记录保留逐岗位 `scope_checks`、`pending_verification` 和具体原因。

## 补投继承与授权分离

本会话最近一次批量投递调用的实际范围保存为 `dialogue.delivery_scope`，包含会话、简历版本标识、搜索来源、分数和条件树。单独投递某个序号不覆盖此批量范围。

- 默认 `scope_mode=inherit`：例如“还有两个88分的没投”，保留旧筛选条件，与新增条件取交集；分数门槛不因省略降低，搜索来源也不因省略漂移到其他轮次。
- `scope_mode=new`：用于用户明确另起独立范围、取消/替换限制或降低门槛。模型负责解释这种语义，不增加一套自然语言正则否决规则。
- 新搜索、明确另一轮结果及指定单岗位不自动继承无关批次。
- 新规划和动态修订都在生成动作绑定前展开实际参数。展开后的参数冻结，后续“当前范围”指针变化不能改写已规划动作；原生工具入口也在授权前执行同一数据继承。
- 会话或简历变化需要核对，不把旧范围当作授权。范围记忆不能发消息，不能恢复被停止的执行器，也不能让未来未搜索岗位自动入队。

真实站投递仍关闭；模拟站的预览、一次性授权、简历绑定、验证接管和结果不确定保护不变。

### 模型不能用 new 标志跳过旧批次限制

授权入口读取服务端持久化的旧批量范围，与本次实际参数比较，不把 `scope_mode` 或 `user_requested` 当作更换范围的许可。保持原条件、提高分数门槛、结构上可证明收紧条件时不额外询问；降低门槛、移除或无法证明保留旧条件、改变搜索来源或会话/简历绑定时生成范围确认卡，列出旧条件与本次范围，等待人工确认，而不是直接拒绝。

比较支持布尔结构和同作用域薪资边界收紧，不猜测自然语言改写是否等价。不增加用于判断“用户说得够不够明确”的正则规则。指定单岗位仍使用独立的有界对象选择契约，不被旧批量条件静默约束。

需要人工确认的原因只由服务端写入授权快照，模型不能填写；重复调用、重启或会话当前范围指针变化不会将其提升为指令自动批准。人工批准只适用于完全相同的动作、参数、简历及来源，参数变化需要重新核对；拒绝不会发送。旧版仅凭指令自动批准的记录不能冒充此次范围变更的人为确认。

## 历史兼容与部署

后端启动时增加可空 `jobs.source_tags` 列，保留全部原有记录。旧记录缺失原始标签时保持 NULL，不从派生标签伪造原始事实。旧策略版本的判断不得直接复用，后续明确重新筛选时重核；不会后台自动补投。

旧会话在本次版本前未保存 delivery_scope 时，不凭任意一条旧聊天推造执行范围。新版本的批量调用会保存范围；必要时由用户明确一次当前范围。新增列不改变已批准队列的状态，也不改写已完成发送回执。
