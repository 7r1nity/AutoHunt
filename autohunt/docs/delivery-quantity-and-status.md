# 投递数量、本轮范围与聊天状态交付

## 行为契约

- “投递20个/20份”最多将本轮20个已核实、未投递且不在队列中的岗位入队。数量独立于搜索数量、分数、薪资和数据库ID。
- “投递前20个”使用同一数量契约；在本轮稳定列表顺序中，先核对条件与历史，再选最多20个。没有展示列表时按该轮冻结分数降序、岗位ID升序选择。
- “投递第20个”仍是严格单岗引用。不会将第20个理解成20份，也不会将详情或移除操作的“前N个”改为宽松引用。
- 本轮合格岗位只有1个时入队1个，报告尚差19个；没有合格岗位时报告缺20个。不重新搜索、不从其他轮次补齐，不把用户明确条件证据不足的岗位算作合格。
- 入队数量、已发起沟通、等待HR回复和已核实投递分开表达；入队不代表招聘方已收到简历。

## 数据与执行

1. 模型选择工具与语义范围，公开工具参数使用 `limit`（1–200）。共享命令语义仅恢复用户本轮明确的投递数字，不从薪资、分数或历史职位文字推断数量，不创建新动作或授权。
2. 规划与修订共用数量归一化。多个投递分支只能使用各自明确的数量；同一总量被拆成多个步骤时，反馈内部修复，要求合并为一个步骤与条件树，避免每分支复制额度。含糊数量与附加岗位限定不能被静默覆盖。
3. 搜索中追加投递保持原依赖，等待搜索完成。执行器在授权前冻结 `source_task_id`、适用的 `snapshot_id` 和参数绑定；后续另一轮搜索及聊天列表更新不重定向该动作。
4. 数量批次只接受当前会话、当前简历的已完成搜索回执。已冻结来源消失时等待核对，不回退到另一轮；跨会话、简历变化、JD事实变化和停止请求仍受保护。
5. 队列在本轮回执中处理用户明确条件、分数、既有发送与队列记录，然后截取数量。选中ID、来源和上限写入队列范围；默认 JD 资历诊断仅供参考，不因学历、应届或项目证明未知而拒绝入队。用户条件未知仍不入队。已知低于分数门槛的岗位计为不符合，而非证据不足。当前策略见[资历建议说明](qualification-policy.md)。
6. 用户明确要求新的、可信本轮数量批次时，不再与无关上一轮投递范围比较。原批次真正扩大范围、缺少授权、错误简历、未确认副作用等仍保留对应确认与核验。

成功的数量批次会记录本次投递范围，包含“前N个”入口，以便后续“其余继续投”继承正确批次；数量上限不会变成未来职位的常驻投递规则。

## 等待、失败与去重

后台计划处于待补充、待审批、待登录/验证码、待绑定或暂停时，立即发布中间 `workflow_summary`，写入聊天历史，保留真实等待状态。独立分支失败也保留原因，不能只显示此前搜索总结。

同一执行状态使用稳定回执及 `message_id`，轮询、恢复和刷新不重复发布；中间消息不替代最终结果。状态改变后可发布新的等待原因或最终结果，已取消或被修订的旧状态不再发布。前端沿用现有稳定消息ID合并机制。

## 验证与边界

新增四组离线契约并接入 `context_ledger_regression` 与 `workflow_upgrade_acceptance`：

| 模块 | 检查范围 |
| --- | --- |
| `delivery_request_contract` | 用户指令 → 真实MainAgent规划/修复 → 运行器 → 授权 → 隔离SQLite队列 → 聊天持久化；搜索中追加与跨轮结果竞争 |
| `delivery_round_contract` | 本轮来源、快照、旧范围、严格单岗、授权绑定与来源丢失 |
| `delivery_limit_contract` | 条件后截断、短缺、重复、未知资格、停止/材料变化 |
| `workflow_wait_delivery_contract` | 后台等待/失败消息、稳定ID、恢复与终态交付 |

模型输出为脚本化合成数据，账号绑定为测试替身，不访问个人材料、不调用外部模型、不执行真实招聘操作。这些工程检查验证数据传递与状态契约，不能当作真实LLM理解准确率或真实网站端到端成功率。

前端回放与浏览器沟通/回复/发送验收使用独立浏览器上下文和拦截的合成接口，分别验证可见聊天与原投递流程；不向现有队列发送内容。详细运行结果与日志保留在本地忽略目录 `agent/evaluation/results/`。

在 `autohunt/agent` 使用项目Python环境运行：

```text
python -m evaluation.context_ledger_regression
python -m evaluation.delivery_request_contract
python -m evaluation.workflow_wait_delivery_contract
python -m evaluation.delivery_status_ui_browser --origin http://127.0.0.1:3000
python -m evaluation.gated_delivery_browser_contract
```

前端回放需要已启动的本地前端，并读取前两项专项生成的合成轨迹；所有业务接口均被拦截。`context_ledger_regression` 只执行离线工程契约，记录源码哈希与逐模块日志，不启动浏览器或外部模型。
