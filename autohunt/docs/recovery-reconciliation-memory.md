# 受限恢复、只读对账与长期语义记忆

源码基线：2026-10-21 的本次实现。三项共用既有运行记录和授权入口，不新增绕过发送保护的快捷通道。

## 1. 受限恢复决策

`workflow/failure_recovery.py` 根据步骤状态、工具 effect、失败分类和持久预算给出 retry / replan / clarify / reconcile / stop / wait。没有用自然语言正则重新判断用户是否下令。

- 自动重试仅限原有幂等读取白名单、暂时失败且底层重试未耗尽；参数不变。单步骤最多一次自动恢复，整份计划最多三次，预算在推理或等待前写入 checkpoint，重启不清零。
- 自动局部重规划仅修复已注册只读工具的错误参数，不允许换工具、改对象/结果来源/筛选范围、改原本有效的参数或加入额外可选参数。修复后重新通过普通 Schema、策略和执行入口，使用新执行标识；不重放已完成步骤。
- 局部模型修复最多 12 秒，失败转为具体的等待输入，不在后台无限修复。暂时网络错误的底层最多三次尝试不与新恢复预算成倍叠加。
- 已撤回、越权、简历/账号冲突不交给模型自动绕过；写入和投递不自动改参。结果未知只能对账或人工核验。

这不是通用自主重规划器：不会让模型为失败的发送重新挑选岗位、放宽条件，或随意替换整份 DAG。可扩大范围的业务变化仍需新的用户指令和正常范围确认。

## 2. 模拟站未知投递的只读对账

发送前持久化模拟站账号、简历 ID、文档版本/摘要及导出简历内容指纹。`delivery/reconciliation.py` 只向固定本地模拟站发 GET，读取账号、本人投递和本人简历；不跟随重定向、不采用岗位提供的域名，不点击网页、不创建简历或授权。

确认成功必须同时满足：账号和角色一致、岗位一致、投递记录唯一、简历 ID 和导出内容指纹一致、简历中的 AutoHunt 文档版本绑定一致。

| 观察结果 | 处理 |
|---|---|
| 完整绑定一致的投递凭据 | CAS 事务更新原 run、看板和原队列为完成，不重新发送 |
| 未发现投递记录 | 保存 not_observed，仍保留未知，不解释为安全重发 |
| 账号/简历/内容冲突 | 保存 conflict，等待核验 |
| 接口断开、超时、鉴权失败或凭据畸形 | 保存 unknown，不改变发送状态 |
| 旧记录没有发送前指纹 | 不伪造绑定，继续人工核验 |

后台按公平调度检查，每轮最多三项、同一项至少间隔 30 秒；重启后从 SQLite 继续。取消、记录变化或存在更新的同岗位尝试时，旧读取结果不能覆盖新状态。已经移除的岗位不会因此复活到看板。

本机制只适用于模拟站；真实网站提交仍禁用。即使站点确认没有记录，也不自动创建新发送机会。

## 3. 带来源的长期语义记忆

`runtime/semantic_memory.py` 使用现有配置模型，独立于动作授权。运行时在处理新聊天前，最多压缩一批八条旧用户请求，保留最近八条用户请求不入此批。来源通过 SQLite 序号顺序分页，不受最近 100/500 条 UI 记录窗口截断。

- 摘要是可检索主题改写，每项带 source_id 和逐字 quote；来源必须属于同一会话，所有非空来源均须覆盖。错误引用、漏项、模型不可用或六秒超时回退为原文摘录，并持久化结果，避免每轮重复压缩同一批。
- 完整原文保留在原运行记录，记忆也保留来源清单。每条摘要输入最多提供来源前 2500 字，回退摘录最多 300 字；这不是声称已压缩完整长文，原文可单独读取。
- 召回读取最近最多 300 批记忆，混合关键词候选和近期候选，最多二十条摘要交由模型按语义选择；最多四秒，失败回退词项召回。默认最多返回四条，工具上限六条；单次运行内缓存相同查询。不是向量数据库，也不是无限历史的穷尽语义检索。
- `context_memory_read(query=...)` 可再次召回；`context_memory_read(source_id=...)` 读取当前会话原始用户消息。`context_history_read` 原有关键词检索保留。
- 召回结果是 ContextBuilder 的可选区，预算不足先移除，不挤掉原请求、当前槽位、执行记录或工具协议。历史条件不得覆盖最新结构化条件，摘要和来源读取均不能创建授权。
- 会话重置 epoch 后不召回旧条目；“清除历史”把新记忆表一并备份并清空。存储使用 RunStore 既有加密设置，传输继续使用既有按需脱敏副本；不生成明文向量索引。

摘要的逐字来源检查不能独立证明模型改写语义完全正确，所以提供原文核对路径，不把摘要当执行事实。当前只压缩用户原话，不将助手宣称的成功写成长期事实；执行成败仍查执行账本。

正常使用时新增模型开销有明确上限：达到压缩批次才做一次摘要，有记忆时才做召回；模型传输本身的有限重试仍受各调用总期限约束。本次验证使用脚本模型，没有调用用户配置的真实外部模型。
