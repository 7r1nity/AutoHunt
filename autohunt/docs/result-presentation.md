# 工具结果与最终回答

前台计划与异步后续完成共用 `workflow/presentation.py`。动作执行回执与回答整理分开；整理模型没有工具，不能重跑、补做或撤销操作。

模型收到原请求、修订、目标及有界的结果投影，根据具体分支的来源整理回答。成长计划使用它自己筛出的 `job_sources`、分数/月薪范围、差距与总结，不把前置的通用职位列表当作差距样本。仅供分析使用的读步骤由依赖图标为背景，不自动输出长列表。

最终回答仍含程序核实的入队/保存/失败回执；入队不等于已投递。来源只能引用对应结果里的 ID，链接从原始记录生成，可点击。明确查看列表/详情时用原记录渲染，保留稳定序号；模型不得重排编号。

整理调用最多 18 秒，最多 2,400 输出 token，输入投影上限 48,000 字符；超预算、无模型、格式或来源校验失败回退到已记录产物，不影响执行状态、不重跑工具。截断标记显式保留。只有实际发布的列表才更新会话可见快照。

后台先持久化整理结果再发布；同一计划修订/步骤指纹的发布失败接续复用该答案。已发布搜索报告/前台产物不重复输出。取消时不发布迟到答案。

`evaluation.presentation_contract` 使用脚本模型验证内容选择、分支来源、坏格式、超时、取消、前台与后台发布及重启去重。真实模型的语言质量、自由文本事实准确性不是这些结构检查的保证，需要独立模型评估；本轮没有真实模型调用。
