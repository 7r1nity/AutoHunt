# 通用岗位筛选框架

这一层只决定岗位是否满足本次搜索条件，不替代简历匹配评分，也不授予外部写操作权限。

用户原文 → 现有规则/小模型/主模型理解 → 有原文依据的条件树 → 平台只读事实 → 三态判断 → 确定性布尔运算 → 结果数量/统计/动作门控。

## 条件与状态

搜索参数新增 `source: mock | boss | zhaopin` 和 `filters`。会话搜索状态保存这两个字段；省略表示继承，`filters: null` 表示明确清除。原简历仍负责提供岗位方向，不被搜索条件改写。

```json
{
  "op": "all",
  "children": [
    {"op": "condition", "text": "不要劳务派遣", "quote": "不要劳务派遣"},
    {
      "op": "any",
      "children": [
        {"op": "condition", "text": "学校提供住宿", "quote": "学校必须提供住宿或者交通补贴"},
        {"op": "condition", "text": "学校提供交通补贴", "quote": "学校必须提供住宿或者交通补贴"}
      ]
    }
  ]
}
```

`condition` 判断完整 `text`；`quote` 必须是用户或已保存条件中的连续原文，允许 text 补齐共享主语和省略，而不是要求补齐表达也逐字出现在原句。旧叶节点没有 quote 时以 text 为引用。`all`、`any`、`not` 支持嵌套，最多四层、32 节点，每个节点最多16个孩子。not 只能有一个孩子；叶节点已含否定时不能再重复取反。

不枚举行业、公司或福利词作为能力白名单。数值月薪下限仍使用已有的确定性比较；开放语义由独立的无工具模型调用判断。硬条件不是匹配加分项。

## 证据与判断

模型读取标题、公司、地点、薪资、JD 和页面标签。每个叶节点按固定 index 返回 pass/fail/unknown、短说明和字段/连续原文引用。引用不在给定事实中、模型不可用、超时或协议错误都不能产生通过结果。默认 mock 模型不具备语义核验能力，返回待核实。

all：任一失败则失败，全部通过才通过；any：任一通过则通过，全部失败才失败；not：通过/失败互换，未知仍为未知。公司客户不等于雇主；未提及不等于没有；有机会不等于保证。程序核对引用真实性，但没有独立证明语义正确性的能力。

每个岗位最多一次语义判定，25秒截止；真实站读取中的评分/筛选并发数有上限。取消会传播，不无限重试。条件缺证据的岗位保留在看板供核实，但不计入合格数量、薪资/JD统计或成长计划样本。

## 执行与平台边界

模拟投递在入队、预览、授权消费以及沟通/提交前核对筛选状态和职位/条件指纹。沿用简历版本绑定、一次性授权、人工验证接管和不确定结果不重试。按搜索任务保存判定，不允许另一会话修改同一岗位后放大旧任务的投递范围。变更旧证据或条件需要新的搜索/预览/授权，不能自动复用。

BOSS 使用现有适配器；智联新增公开 DOM 适配器和严格详情域名/路径校验。两者共用浏览器资源锁、任务生命周期与匹配/筛选流程。城市页面筛选不可用时加入检索词，并在详情中再核对实际地点；这不是保证检索覆盖所有城市。当前仅读取已加载的有限候选，不承诺全站分页覆盖。

真实站没有开放沟通、上传或提交，dry_run 也只能用于模拟站。登录、验证码、MFA和无法确认的页面状态需要人工接管，不做验证绕过。

## 当前边界与核验

- 硬条件搜索已经接入；通用软偏好排序、投递/成长计划的独立任意条件树尚未接入，现有分支能力限制仍存在。不要把“尽量”擅自当作“必须”。
- 109项一次性隔离检查覆盖布尔真值、引用/树边界、会话继承、未知门控、授权失效、跨任务防串用、日志 JSON 完整性和详情 URL 校验。
- 当前 DeepSeek 配置上核验四类合成 JD；另外三条金融/教育/制造请求通过模型规划→条件判断检查。没有调用搜索执行器、发送消息或投递。
- Python语法/导入、前端类型检查通过；无持续自动化回归测试文件（此前按用户要求移除）。智联登录态 DOM、BOSS真实站完整搜索与准确率/召回率评估仍未验收。
- 额外核验评分/筛选并发子任务的取消及失败传播，不留下脱离任务生命周期的推理工作。
