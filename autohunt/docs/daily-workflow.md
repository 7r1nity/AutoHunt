# 每日模拟站任务

## 当前行为

在前端设置中启用每日任务，并指定北京时间、最低匹配分和联系数量。后端常驻轮询；到时间且浏览器、投递执行器空闲时，按候选人的目标岗位启动本地模拟站搜索，联系高匹配职位，等任务结束后写入会话汇总。每日任务不会注入模拟招聘方回复。

当天已成功启动的任务不会因轮询或重启重复启动。若开启每日任务时已经过了所设时间，当天跳过，从次日开始。电脑关机或后端停止时不会执行；没有通用 cron、跨日补跑或完整的调度租约恢复。

## 2026-11-15 修复

- **启动失败可以重试**：每次启动占位使用独立 `daily_claim_id`。浏览器任务启动前抛错或被取消时，只释放本次占位；不会再被上一轮 `last_run_id` 阻挡。保留上一轮的任务与汇总指针，旧失败回调也不能释放新的占位。浏览器已启动后的记账失败不释放当天记录，避免重复产生外部操作。
- **每日任务遵守自动投递开关**：启动时保存本轮自动投递授权的启用时间。实际收到招聘方回复后，上传/绑定简历前、每次点击发送前重新检查开关及启用时间。关闭开关、关闭后重开、或本轮启动时未开启，都不会给旧一轮补授权。回复与未发送原因保留在本轮报告中。已经开始点击的异常保留“结果待核验”，不自动重投。
- **检查日志准确**：未到时间、已运行或执行器忙时记录“本轮未启动”，不再声称已执行每日汇总。

用户明确发起的手动 Dry Run 保持独立的批次授权；逐职位预览、一次性授权、简历版本绑定、人工验证及不确定结果保护继续生效。真实招聘站投递保持关闭。

数据库新增字段会在下一次后端初始化时自动补齐，不删除历史数据。若进程在占位之后硬崩溃，无法确认是否启动过的当天仍保守跳过；此次未实现硬崩溃后的自动租约回收。

## 验证

在 `autohunt/agent` 下运行：

```powershell
.\.venv\Scripts\python.exe -m unittest evaluation.daily_workflow_contract -v
.\.venv\Scripts\python.exe -m unittest evaluation.delivery_scheduling_contract evaluation.background_polling_contract evaluation.search_delivery_contract evaluation.delivery_evidence_contract evaluation.workflow_execution_contract evaluation.approval_contract -q
```

本次 21 项专项与 144 项相关回归通过（共 165 项）。使用临时 SQLite、合成候选人、模拟浏览器对象；没有外部模型调用、真实浏览器操作或真实投递。覆盖旧库迁移、前次成功后的启动失败、取消、重复触发、过期占位、开关变化、简历变化和点击后的不确定结果。专项已加入跨模块离线回归入口；这些结果不代表真实网站端到端验收。

## 记录范围

每日任务目前保存在 `autohunt.db` 的 `browser_tasks`、`browser_events`、`search_recovery` 和自动化决策记录中，汇总写入默认会话。它直接启动浏览器服务，尚未为每轮创建统一的 `agent_runs` / `RunContext`，因此不能假定主 Agent 指标面板已完整计入每日搜索的所有模型调用、token 和步骤链路。
