# 每日模拟站任务

## 使用入口

前端「模型设置 → 模拟站会话与每日任务」开启会话监测，设置每天的北京时间、最低匹配分、每轮最多联系岗位数并保存。需要自动发送简历时，另行开启「HR 明确回复后，自动在模拟站发送简历」。先准备主简历和目标岗位；登录、验证码与 MFA 由用户完成。

点击 **立即测试每日任务**，按已保存设置创建独立测试轮次，自动切换到「验收与指标」。它会真实操作本地模拟站，不是只检查配置：搜索、发起沟通，获得招聘方回复且本轮自动投递授权仍有效后发送绑定简历。测试不会模拟 HR 回复，也不占用当天的定时执行名额。HTTP 重试使用相同请求 ID，返回原轮次。

可以从「查看最近一轮指标」或「验收与指标 → 默认会话」查看每日任务。任务等待验证时完成浏览器中的登录/MFA，再点继续；等待 HR 回复时会保留状态并定期检查。停止运行使用现有停止按钮；关闭每日开关只关闭后续排程。

## 排程与补跑

- 北京时间固定每天一次，持久化 `daily_next_due_at`（UTC）。新开启或修改时间时安排下一次未来时刻，不补跑启用前的任务。
- 到期先创建 `kind=daily` 的持久轮次，再推进下一次时间。日期请求键唯一；即使创建完成、游标尚未推进时中断，也不会重复创建同一次触发。
- 停机错过多天，**合并为最近一个已到期时刻的一轮补跑**，记录最早错过时刻及合并次数。不会逐日补发多批沟通；每轮仍受联系数量上限约束。
- 浏览器忙时保留队列，空闲后再运行。立即测试、定时触发、补跑分别记录触发类型。
- 后端/电脑停止时不会执行或唤醒电脑；恢复运行后补跑。当前为本地单后端进程调度，不是支持多个调度器竞争的分布式任务系统。

## 崩溃恢复与投递边界

每轮冻结搜索条件、账号、主简历 ID/版本/摘要及自动投递启用时间。检查点写入 `runtime.db` 的 `agent_runs`；浏览器搜索进度、预览授权和投递回执仍沿用 `autohunt.db`。

| 中断位置 | 恢复行为 |
| --- | --- |
| 入队或只读搜索中 | 继续同一轮、同一个浏览器搜索 ID，复用已有职位处理记录 |
| 沟通点击前后 | 点击前先记发送意图；重启先读取站点消息，已有消息不重发；无法证明结果则标记待核验 |
| 等待 HR 回复 | 保留等待状态，检查到实际回复后再进入简历步骤；默认 24 小时未回复转人工确认，不重发问候 |
| 简历提交前后 | 点击前保存 `submit_started` 及绑定指纹；重启只读核验账号、岗位、简历 ID 和内容指纹，完全一致才记成功；没有可靠回执不重投 |
| 已完成或用户取消 | 不自动重新执行 |

搜索、连接等整体恢复连续失败最多 3 次，中间至少间隔 30 秒；浏览器操作保留活动/无进展/人工等待预算。回复等待截止时间持久化，不因轮询或重启重新计时，可用现有 `AUTOHUNT_REPLY_TIMEOUT_SECONDS` 调整默认值。

自动投递在绑定简历前与实际发送前重新核验；关掉后再打开不授权旧轮次，主简历版本变化也会阻止继续操作。单职位预览与一次性授权继续生效。只有本地模拟站可发送，真实招聘站投递保持关闭。

数据库新增字段在初始化时迁移，不删除历史。升级前旧版本已启动的每日任务没有新格式检查点，保留原来的保守核验行为；本次自动恢复适用于升级后创建的每日轮次。

## 指标与历史报告

每日轮次使用与普通 Agent 相同的 `agent_runs`、`agent_run_events`、`RunContext` 和只读账本，属于 `session_id=default`。可以查看状态、模型/工具调用次数、输入输出 token、记录时长、模型累计耗时、失败原因、搜索和各岗位步骤。模型调用带 `run_id / session_id / plan_id / step_id / execution_id`；恢复和工具尝试保留事件。

没有供应商 usage 的调用显示「未记录」，不能把未知 token 当作 0；总记录时长可能包含等待 HR/MFA 的时间。调用成功也不等于投递成功，应结合最终状态和站点回执。

「历史评测」继续展示现有模型评测与工程报告，并新增本机 `evaluation/results/daily-site-e2e/<时间>/summary.json` 的安全汇总。原始 SQLite、浏览器 trace、截图和 HTTP 记录留在本机，不经报告 API 暴露，不提交 Git。

## 可重复测试

从 `autohunt/agent` 运行：

```powershell
# 每日任务专项：临时 SQLite、合成材料、模拟浏览器对象
.\.venv\Scripts\python.exe -m unittest evaluation.daily_scheduler_contract evaluation.daily_workflow_contract -v

# 全部相关跨模块工程回归，无外部模型/浏览器调用
.\.venv\Scripts\python.exe -m evaluation.context_ledger_regression

# 真浏览器 + 独立模拟站 + 生产 API + 前端按钮
.\.venv\Scripts\python.exe -m evaluation.daily_site_e2e
```

端到端测试要求本机已有未随仓库分发的 `mock-site`、其 Python 环境、前端依赖、Node 和 Playwright Chromium。测试自动启动临时端口服务，使用隔离数据库、虚构简历/账号和本地 Mock 模型，不连接用户现有 CDP、8080 站点或外部模型。测试自己的 HR 账号发送回复，生产 Agent 不伪造回复；测试角色完成模拟 MFA，Agent 保持人工接管逻辑。

2026-11-15 跨模块回归 **786 项通过**，其中每日专项 **43 项通过**（22 项新调度契约、21 项已有授权契约）；前端类型检查和生产构建通过。实测一条完整浏览器验收链的 **9 项检查通过**：测试按钮、MFA 暂停、先沟通后等待、等待期间恢复不重复沟通、HR 回复后投递绑定简历、提交成功但本地未记成功时中断后的只读恢复、完成轮次不重放、错过 4 天合并一轮并实际完成补跑、前端历史报告加载。链中只有一笔模拟申请。故障采用在真实提交返回处注入取消并重建调度/存储对象，不等同于操作系统强杀、断电或数据库损坏测试。Mock 模型不返回 token usage，本轮不测真实模型语义准确率。
