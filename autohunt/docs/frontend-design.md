# AutoHunt 前端设计

2026-10-11，按用户指定的 `frontend-design` skill 重构。范围仅 AutoHunt 前端；不改变路由、授权、搜索、投递和历史数据。

## 设计计划

面向个人求职者的工作空间，而不是展示 AI 能力的宣传页。突出简历、机会、申请三步的真实进度，核心动作始终用用户熟悉的名称。

| Token | 颜色 | 用途 |
|---|---|---|
| Canvas | `#EDF2F8` | 冷色工作区底色 |
| Paper | `#FFFFFF` | 内容与阅读面 |
| Ink | `#172B46` | 主文字 |
| Muted | `#63738A` | 辅助说明 |
| Action | `#2463CC` | 主要按钮与当前导航 |
| Line | `#DCE4EF` | 信息分区 |

字体：Trebuchet MS 用于品牌、英文与数字，Microsoft YaHei UI/PingFang SC 用于中文正文；全部本地字体，无远程字体请求。字号层级为工作台主行动 38px、页面标题 24px、区域标题 18px、正文 14–16px、辅助文字 12px。

比较过「顶栏导航 + 均匀卡片」和「固定导航 + 求职流程」；选择后者，七个页面入口长期可见，对话保留独立阅读空间。

```text
导航         工作台标题 / Agent 状态
             下一步主行动       简历 → 搜索 → 申请
             本轮统计（紧凑信息带）
             岗位能力分布       简历 / 成长 / 配置入口

导航         对话标题 / Agent 状态
             会话操作
             对话阅读区         可收起的任务详情
             多行输入框
```

全局左对齐，阅读内容控制在约 70 字符；工作台、对话、看板使用不同空间密度，不把所有内容塞进同一种卡片。

## 自检与约束

- 拒绝通用玻璃渐变、反复叠加黑色/紫色主题和每栏大写标签：移除旧视觉覆盖，保留文档打印/简历及功能布局；`workspace.css` 是唯一工作区视觉层。
- 只在主行动区使用明显的视觉层次，其余背景安静；没有虚构市场趋势、进度或职位。
- 空状态提供明确去向；快捷示例只填入消息，不发起搜索、投递或成长计划。
- 多行输入：Enter 发送、Shift+Enter 换行，中文 IME 不误发送。任务执行中仍保留停止命令通道。
- 保留登录接管、投递预览、一次性授权、历史清除确认和简历提案审批；视觉重构不扩大操作权限。
- 响应式导航、可滚动看板、键盘焦点、跳到内容链接、减少动态效果与简历打印样式。

## 本次验证

- `pnpm typecheck` 与生产构建通过。浏览器使用本机服务，未调用外部模型、未发送消息、搜索、投递或修改业务数据。
- 默认桌面视口 1280×720 和手机视口 390×844：工作台、对话、申请看板、简历、统计、成长计划、模型设置均检查；文档宽度不超过可视宽度。普通页面的滚动条占用 15px 为正常现象，看板仅在自身区域横向滚动。
- 桌面对话阅读区约 1002px，输入框约 930px；任务侧栏开关可用。实测 Shift+Enter 保留换行，消息数不变，检查草稿随后清空；空白输入禁用发送。中文 IME 防误发由事件守卫保护，本次未进行真实输入法端到端测试。
- 使用现有六条职位检查已填充看板；Enter 打开岗位详情与原始链接，不触发投递。各页面只导航/阅读，不点击生成、上传、同步、审批、清除或发送操作。
- 查看工作台、对话、手机对话/看板、简历页面截图。搜索执行信息折叠保留所有字段，等待人工接管时默认展开，历史失败记录不占大块首页空间。
- 界面预览保存在本机 `_diag/frontend-design/`，不提交截图或用户数据。上传中的反馈、空对话示例、成长计划完成/提案及打印流程本次没有以真实业务写入逐项验证；这不是搜索/投递全链路 E2E 验收。
- 检查时遇到迁移后的 Turbopack 开发缓存异常，临时改用已安装 Next 的 Webpack 开发模式启动，仅重启前端。没有修改启动脚本/依赖或重启后端、模拟站。
